# 학습 저장소

## 데이터 분리

| 데이터 | 저장 위치 |
| --- | --- |
| 공식, 문제, 분류, 해설, 입력 추천 프로필 | `src/database/data/`의 TS 파일 |
| 내 학습, 본 문제와 답안, 풀이 통계, 유도 진행 | 토스·샌드박스: SDK `Storage` / 일반 브라우저: `localStorage` |

콘텐츠 JSON 내보내기에는 학습 기록이 포함되지 않는다. 학습 기록은 기기 로컬 데이터다. 토스 계정 로그인이나 서버 동기화를 구현한 것은 아니다. 현재 익명 ID는 한 저장소의 학습자를 식별한다. 같은 기기를 함께 쓰는 사람을 구분하지 않는다. v3 풀이 통계는 기존 기기 단위 키를 유지한다. 향후 로그인 도입 시 소유자 이전 정책을 정해야 한다.

## 코드 흐름

1. `storage-runtime.ts`에서 SDK의 실행 환경을 확인한다. `toss` 또는 `sandbox`이면 SDK `Storage`를 선택한다. 일반 브라우저는 `localStorage`를 선택한다.
2. 토스에서는 같은 origin에 있는 이전 브라우저 기록을 한 번 옮긴다.
3. `learning-state.ts`에서 익명 ID, 내 학습, 열람 기록, 통계와 유도 진행을 읽는다.
4. 읽기가 모두 끝나면 `AppLoader.tsx`가 앱을 연다. 읽기 실패는 빈 데이터로 바꾸지 않는다. 재시도 화면을 표시한다.
5. 화면 조작은 메모리 상태에 바로 반영한다. 실제 저장은 `storage.ts`의 비동기 인터페이스를 사용한다.

`getItem`과 `setItem`은 Promise를 반환한다. 같은 키의 저장 요청은 순서대로 실행한다. 이전 저장이 실패해도 다음 저장을 실행한다. 저장 중 해당 키를 읽으면 대기 중인 저장이 끝날 때까지 기다린다. SDK 저장 실패 시 브라우저 저장소로 자동 전환하지 않는다. 실패한 기록은 화면에서 다시 저장할 수 있다. 앱을 저장 완료 전에 닫으면 대기 중인 변경이 사라질 수 있다.

기존 데이터 형식 검사는 유지한다. 잘못된 JSON과 유효하지 않은 항목은 기존 규칙에 따라 제외한다. 저장소 접근 자체의 실패는 초기 로딩 실패로 처리한다.

## 기존 기록 이전

- 현재 origin에서 읽을 수 있는 기존 익명 ID의 내 학습, 본 문제, v3 통계, 유도 진행만 옮긴다.
- SDK에 값이 있는 키는 덮어쓰지 않는다.
- SDK의 익명 ID가 기존 브라우저 ID와 다르면 기록을 합치지 않는다.
- 데이터 복사가 끝난 뒤 익명 ID와 완료 표식을 기록한다. 중간에 실패하면 다음 시도에서 누락된 키를 이어서 복사한다.
- 이전이 완료되면 다시 복사하지 않는다. 과거 기록이 재생성되는 일을 막는다.
- 브라우저 원본과 다른 앱의 데이터는 삭제하지 않는다. 이전 v1·v2 총점도 그대로 둔다.

PC의 localhost 기록을 휴대전화로 전송하는 기능은 아니다. QR 테스트 주소와 출시 주소의 웹 저장소는 서로 다르다. 현재 접근 가능한 origin의 기록만 이전한다.

## 저장 시점

- 문제를 열 때: 본 문제 목록과 당시 공식·해설 스냅샷.
- 답을 확인할 때: 마지막 제출 답안, 정오답, 힌트 사용.
- 라운드를 마칠 때: 문제별 풀이 횟수와 복습 통계.
- 내 학습을 만들거나 편집·삭제·시작할 때: 설정과 최근 학습 ID.
- 유도에서 다음 줄을 열거나 처음부터 시작할 때: 완성한 줄의 답안.

제출하지 않은 입력, 현재 라운드의 화면 위치, 유도에서 아직 다음 줄을 열지 않은 답안은 복원하지 않는다.

## 검증

자동 테스트는 기존 데이터 검사 외에 비동기 저장·복원, 저장 순서, 저장 실패 후 회복, 초기 읽기 실패와 재시도, 익명 ID 보존, 다른 ID의 기록 분리, 이전 도중 각 쓰기 지점의 실패와 재시도를 검사한다. SDK 형태의 비동기 테스트 저장소를 사용한다.

2026-09-10 검증: 자동 테스트 46개, 린트, 타입 검사와 웹·앱인토스 빌드 통과. Chrome의 localhost:5187에서 기존 내 학습 4개, 본 문제 16개, 유도 4/4 완료를 복원했다. 옴의 법칙 복습에 RI를 입력해 정답 판정과 라운드 완료를 확인했다. 새로고침 뒤 보관함의 마지막 답안이 기존 IR에서 RI로 갱신돼 있었다. 콘솔 오류는 없었다.

실제 토스·샌드박스 기기에서는 문제 풀이 → 앱 종료 → 재실행, 내 학습 복원, 유도 이어 풀기, 기존 웹 기록의 첫 이전을 추가 확인해야 한다. 브라우저 검증이 네이티브 저장소의 실기기 검증을 대신하지 않는다.
