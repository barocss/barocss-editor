# 공식과 문제를 계속 추가하는 구조

## 분류와 출제는 별개다

| 정보        | 뜻                                               | 예                                |
| ----------- | ------------------------------------------------ | --------------------------------- |
| 과목        | 학습하는 과목                                    | 수학, 물리, 화학, 통계, 전기·전자 |
| 분야        | 과목 안의 지식 영역. 여러 과목에 연결할 수 있다. | 대수, 정수론, 회로                |
| 학습 수준   | 공식의 학습 대상. 여러 수준에 연결할 수 있다.    | 초등, 중등, 고등, 대학, 전문      |
| 주제        | 사용자가 고르는 학습 묶음                        | 곱셈 공식과 인수분해              |
| 공식        | 조건과 의미를 가진 하나의 관계식                 | 합의 제곱                         |
| 문제        | 공식의 특정 부분을 묻는 하나의 변형              | 중간 항, 계수, 인수 빈칸          |
| 문제 난이도 | 해당 문제의 입력·변형 난이도                     | 입문, 기본, 응용, 도전            |
| 라운드      | 이번에 푸는 문제 묶음                            | 5, 10, 20문제                     |

공식 수와 연습 문제 수는 다르다. 현재 공식 19개와 일반 문제 37개가 있다. 한 번에 5문제를 고르는 설정은 전체 문제 수를 제한하지 않는다. 현재 학습 수준은 넓은 제품 분류다. 국가·교육과정 개정·학년·학기별 배치를 검증한 것은 아니다. 정확한 학교 진도 기능에는 별도의 교육과정 매핑이 필요하다.

파일 DB의 조회 경로와 내보내기는 [정적 DB 안내](static-database.md)를 참고한다.

## 파일의 역할

- `src/content/types.ts`: 콘텐츠 스키마.
- `src/database/data/packs/taxonomy.ts`: 공통 과목·분야·학습 수준. 같은 ID는 한 곳에서만 선언한다.
- `src/database/data/packs/algebra.ts`: 대수 주제·공식·문제·입력 프로필.
- `src/database/manifest.ts`: 사용할 콘텐츠 묶음을 등록하는 곳.
- `src/content/catalog.ts`: ID와 참조 검증, 공개 문제 선택, 분류 필터.
- `src/game.ts`: 라운드 구성, 채점, 문제별 기록. 특정 과목명과 문제 수에 의존하지 않는다.
- `src/AnswerEditor.tsx`: 문제의 입력 프로필로 키패드와 구조 추천을 구성한다.

현재 묶음은 TypeScript 파일이며 앱 빌드에 포함된다. 추가 후 재빌드·배포가 필요하다. 서버에서 실시간으로 받는 구조나 관리 화면은 아직 없다. 서버를 추가할 때도 같은 ID와 버전 규칙을 유지한다. 외부 JSON에는 별도의 런타임 형식 검증, 캐시, 호환 버전 처리가 필요하다.

## 새 콘텐츠를 추가하는 순서

1. 기존 공식과 같은 관계식인지 확인한다. 같은 공식의 새 빈칸이면 기존 `formulaId`를 쓴다.
2. 새로운 분야나 과목이면 공통 분류에 ID를 추가한다. 기존 분류는 ID로 참조한다.
3. `src/database/data/packs/`에 파일을 만들고 `ContentPack` 타입을 적용한다. 기존 공통 분류를 다시 선언하지 않는다. 해당 배열은 비워도 된다.
4. 새 공식에 고정 ID, 개정 번호, 수식, 조건, 변수 의미, 필요 단위, 출처, 학습 수준, 주제, 선수 공식 ID를 적는다.
5. 문제에 별도 고정 ID, 공식 ID, 빈칸 앞뒤 수식, 난이도, 조건, 힌트, 해설, 허용 답안과 입력 프로필 ID를 적는다.
6. 처음에는 `status: 'draft'`로 둔다. 실제 키패드로 모든 정답을 입력하고 오답·경계 조건도 확인한다.
7. 검토한 공식과 문제를 `published`로 바꾼다. 공개 문제는 공개 공식만 참조할 수 있다.
8. `src/database/manifest.ts`의 `contentPacks`에 묶음을 등록한다.
9. `npm run validate:content`, `npm test`, `npm run lint`, `npm run build`를 실행한다.

공식 등록 시 조건을 생략하지 않는다. 예를 들어 실수에서 제곱의 제곱근은 절댓값이 필요하다. 물리 공식에는 적용 가정과 변수 단위가 필요하다. 출처 URL만 저장했다고 수학적 검토를 마친 것은 아니다.

## ID와 개정 규칙

- ID는 배열 순서, 표시 이름, 난이도에서 만들지 않는다. 예: `math.algebra.square-sum`, `physics.ohm.product`.
- 서로 다른 콘텐츠에 같은 ID를 재사용하지 않는다. 같은 종류 내에서 ID는 유일해야 한다.
- 문제를 새로 추가하면 새 ID와 `revision: 1`을 사용한다. 기존 문제와 공식의 개정 번호는 올리지 않는다.
- 정답·조건·빈칸의 의미를 바꾸면 해당 문제의 `revision`을 올린다. 공식 자체의 의미나 조건을 바꾸면 공식의 `revision`을 올린다.
- 표시 문구만 다듬고 학습 의미가 같다면 개정 번호를 유지할 수 있다.
- 묶음을 수정하면 묶음의 `revision`을 올린다. 묶음 개정은 기존 풀이 기록을 초기화하지 않는다.
- 내릴 콘텐츠는 `retired`로 둔다. 폐기한 문제도 ID를 재사용하지 않는다.
- 스키마 자체가 달라지면 `schemaVersion`을 바꾸고 로더의 호환 처리를 먼저 구현한다.

풀이 기록 키는 `문제ID@문제개정:f공식개정`이다. 새 콘텐츠를 추가해도 기존 기록은 남는다. 의미가 바뀐 개정판은 새로 푼다. 이전 개정의 기록도 저장소에서 삭제하지 않는다. 이전 v1·v2 총점은 보존하되, 개별 정오답을 추정해서 옮기지 않는다. 한 라운드를 마치면 기록을 저장한다. 기록은 토스·샌드박스의 SDK Storage 또는 일반 브라우저의 localStorage에 있으며 기기 간 동기화는 없다.

## 입력과 채점의 확장 경계

입력 프로필에는 문자, 숫자, 연산 버튼과 `square`, `fraction`, `root` 구조를 선언한다. 현재 지수 추천은 제곱이다. 일반 지수, 적분, 합 기호, 행렬 등은 별도 입력 기능 구현과 UI 검증이 필요하다. 긴 수식은 좁은 화면에서 확인한다.

현재 채점은 문제별 허용 답안 목록이다. `polynomial-ab-v1`은 기존 a·b 다항식 표기를 제한적으로 정규화한다. `latex-layout-v1`은 공백과 `left/right` 표기만 정리한다. 입력 문자열을 실행하지 않는다. 모든 수학적 동치를 판정하는 기능은 아니다. 새 정규화나 기호 계산 채점은 명시적인 새 방식으로 구현하고 검사 목록에 등록한다.

기존 대수 문제는 모든 허용 답안에 대해 독립된 다항식 전개 검사를 한다. 물리·화학·통계 문제에는 분야에 맞는 검증을 추가해야 한다. 공개 콘텐츠에 옴의 법칙과 운동 에너지, 산술평균과 표준점수 문제가 포함돼 있다.

## 출제와 검증

- 이어 익히기: 풀지 않은 문제, 적게 푼 문제를 우선한다.
- 섞어 풀기: 선택한 범위에서 순서를 섞는다.
- 복습하기: 마지막에 틀렸거나 힌트를 본 문제를 고른다.
- 공통: 같은 풀이 횟수 안에서는 서로 다른 공식의 문제를 먼저 배치한다. 같은 문제를 한 라운드에 중복하지 않는다. 부족하면 실제 문제 수를 표시한다.
- 선수 공식 ID는 관계를 기록한다. 아직 학습 잠금이나 선수 지식 진단에는 사용하지 않는다.
- 힌트 없이 맞힌 공식 수는 해당 공식의 문제를 하나 이상 맞힌 수다. 숙달률이나 학습 효과를 뜻하지 않는다.

검사 범위: 중복 ID, 잘못된 참조, 선수 관계 순환, 누락 필드, 지원하지 않는 채점·입력 방식, 비공개 문제 제외, 새 과목 연결, 64개 문제 추가, 기록 보존, 개정 분리, 기존 20문제 항등식.

## 사용자가 본 문제와 공식 해설

`FormulaDefinition.lesson`은 선택 필드다. `title`, `introduction`, `steps`로 유도 과정을 쓴다. 각 단계에는 설명 `text`와 선택 수식 `latex`를 넣는다. `history`에는 역사 이야기와 그 근거 URL을 넣는다. 역사적 인물의 행동을 추정해서 사실로 쓰지 않는다. 새로운 그림은 지원 목록과 렌더러를 함께 구현한다. 현재 `pythagorean-area` 그림을 지원한다.

현재 공개한 공식 19개에는 모두 해설이 있다. 피타고라스 문항은 직각삼각형이라는 조건이 있으므로, 모든 실수에서 성립하는 다항식 항등식 검사와 분리한다. 넓이 증명의 전개와 실제 채점을 별도로 검사한다.

`src/history.ts`는 사용자 ID를 인자로 받아 열람 기록을 읽고 쓴다. 현재 앱은 선택된 기기 저장소에 무작위 익명 ID 하나를 저장한다. 같은 기기의 저장소를 함께 쓰는 사람을 구별하지는 못한다. 실제 계정별 기록이나 기기 간 공유에는 로그인과 서버 저장소가 필요하다. 클라이언트의 사용자 ID를 서버 인증 근거로 사용해서는 안 된다.

- 문제가 화면에 나올 때 즉시 본 문제 목록에 추가한다. 라운드 완료를 기다리지 않는다.
- 정답 확인 시 마지막 답안, 정오답, 힌트 사용 여부를 기록한다.
- 문제 ID·문제 개정·공식 개정으로 중복을 구별한다. 같은 버전을 다시 보면 마지막 본 날짜만 갱신한다.
- 당시 문제와 공식 해설을 복사해 함께 저장한다. 원본 콘텐츠가 바뀌거나 출제에서 내려가도 내용을 읽을 수 있다.
- 다시 풀기는 현재 공개 버전을 사용한다. 개정이 다르면 화면에서 알린다.
- 토스 앱을 삭제하거나 브라우저 저장소를 지우면 해당 기록도 사라진다. 읽기 실패는 재시도 화면에서 처리한다. 저장 실패는 안내와 다시 저장 버튼을 표시한다.
- 이전 v3 라운드 점수에는 실제 답안이 없으므로 본 문제 기록으로 추정 변환하지 않는다. 보관함은 이 기능을 적용한 뒤 본 문제부터 기록한다.

기존 라운드 통계는 `game.ts`의 기기 단위 v3 기록이다. 본 문제 보관함과 별도다. 로그인 도입 시 두 저장소의 소유자·이관 정책을 함께 정해야 한다.

## 확장 가능한 학습 조합

새 학습 수준은 `ContentPack.learningLevels`에 `{id, name}`으로 등록한다. 공식의 `schoolLevels`는 이 ID를 참조한다. 코드의 고정 enum을 수정할 필요가 없다. 분류 ID는 전체 묶음에서 유일해야 한다.

개인 조합은 `src/presets.ts`의 `StudyPreset`을 사용한다. 여러 `StudyScope`를 합치고 문제 ID로 중복을 제거한다. 저장된 조건은 현재 공개 콘텐츠에 적용한다. 문제 추가 때 개인 설정을 다시 쓰지 않는다. 누락된 분류 ID를 자동으로 지우면 범위가 넓어질 수 있으므로 그대로 보존하고 표시한다. 조합 저장소는 익명 사용자 ID별로 분리한다. 조합 삭제는 본 문제와 풀이 통계를 삭제하지 않는다.

## 학교 단원과 유도 연습 추가

학교 과목은 학문 분야와 별개다. `src/database/data/curriculum.ts`의 schoolCourses에 판본·출처를 넣고 courseUnits에 과목 ID와 공식 ID를 연결한다. 학년별 문항 제한이 필요하면 questionIds도 지정한다. 이 목록을 사용하면 새 문항도 검토 후 연결해야 출제된다. 단원 전체 선택은 나중에 추가된 단원도 포함한다. 특정 단원 선택은 그 단원만 유지한다. 연결 검증은 build에서 수행한다.

유도 연습은 `src/database/data/derivations.ts`의 단계 정의를 사용한다. 일반 문제와 원본 공식·입력 프로필을 공유한다. 단계 추가나 정답 변경 시 유도 개정 번호를 올린다. 진행 저장은 개정 번호별로 분리한다. 화면의 잠금은 학습 안내이며 정답 데이터를 숨기는 보안 기능은 아니다. 현재는 피타고라스 넓이 증명 전용 진입점과 그림을 제공한다.

## 공통 분류 원본

과목·학습 수준·분야는 `src/database/data/taxonomy/`의 독립 목록에 등록한다. [분류 기준과 연결 규칙](taxonomy-design.md), [전체 목록](taxonomy-catalog.md)을 참고한다. `npm run catalog:report`로 검토용 목록과 문제 연결표를 생성한다. 문제별 `classification`은 원본 공식보다 주제·수준을 좁힐 때 사용한다.

저장 API는 비동기다. 초기 로딩, 기존 기록 이전 및 저장 순서는 [학습 저장소](./learning-storage.md)에 정리했다.
