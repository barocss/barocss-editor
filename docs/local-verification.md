# 로컬 사전 검사

PR을 push하기 전에 저장소의 `.nvmrc`에 지정한 Node를 사용한다.

```sh
nvm use
pnpm install --frozen-lockfile
pnpm preflight
```

`preflight`는 검사 도구 테스트 → 실제 ESLint → 전체 소스 타입 검사 → 전체 테스트 타입 검사를 실행한다. 실패하면 다음 단계로 진행하지 않는다. 코드 수정 후 다시 실행한다. 변경에 맞는 단위·브라우저 테스트도 별도로 실행한다. CI는 로컬 검사의 대체물이 아니라 Linux 환경과 통합 결과를 확인하는 추가 관문이다. 필수 CI를 생략하거나 실패 상태로 병합하지 않는다.

## 기존 부채

- 이전 `pnpm -r lint`는 하위 패키지에 lint script가 없어 검사하지 않았다. 새 명령은 Git에 등록된 파일과 아직 등록하지 않은 파일 중 JS/TS 파일을 검사한다. Git/ESLint의 제외 규칙과 빌드 결과물은 검사 대상에서 제외한다.
- 최초 실측 오류 540개를 `lint-baseline.json`에 기록했다. 파일·규칙·메시지·개수가 같은 기존 오류만 허용한다. 새 오류나 같은 오류의 개수 증가는 실패한다. 위치만 이동한 오류는 동일하게 취급한다. 기존 오류를 고쳤다면 `pnpm lint --adopt`로 목록을 줄인다. 이 명령은 새 오류를 등록하지 않는다. 같은 파일의 동일한 메시지가 사라진 자리에 동일한 오류가 생긴 경우까지 구분하지는 않는다.
- 경고는 표시하지만 실패로 처리하지 않는다. `pnpm lint --strict`는 기존 오류도 모두 실패로 처리한다. 정상 lint 통과는 오류가 0개라는 뜻이 아니다.
- 소스 타입 검사에는 기존 데모 앱 3개의 예외가 남아 있다. 테스트 타입 검사는 `typecheck-budgets.json`의 기존 오류 한도를 유지한다. 두 기준을 올려서 변경을 통과시키지 않는다.
- 컴파일러 실행 실패, 강제 종료, 설정·명령 오류는 기존 부채로 허용하지 않는다. 설치된 TypeScript만 사용하며 검사 중 패키지를 내려받지 않는다.

Git hook을 자동 설치하지 않는다. 작업 규칙과 동일한 CI 명령으로 검사를 유지한다. `preflight`는 publish, 서비스 배포, 버전 변경을 실행하지 않는다.
