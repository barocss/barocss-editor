# Wonffice 남은 구현 범위와 종료 기준

2026-09-19 추가 결정: 클라우드 SaaS와 고객사 내부 설치를 **동시에 출시한다**. 아래 4–5단계는 [플랫폼 설계](wonffice-platform.md)와 [WP 구현 순서](wonffice-platform-delivery.md)로 구체화했다. GitHub 기반 자동 개발은 [Agent 실행 계약](wonffice-agent-runtime.md)을 따른다. 현재는 설계 기준 작성 상태이며 서버·자동 실행·출시 완료가 아니다. 모바일 화면 설계와 크기 검사는 현재 작업 범위에서 제외한다.

기준일: 2026-09-13. 사용자 요청: 로드맵에 남은 기능을 어디까지 구현할지 정리한다.

## 목표와 상태 해석

전체 개발 목표는 Note·Word·Slides·Site를 같은 팀 공간에서 만들고, 편집하고, 저장하고, 공유하는 서비스다. 첫 출시의 종료 기준은 아래 1–5단계를 검증한 상태다. 후속 고급 기능과 새 제품은 6단계로 유지한다. 개발 순서를 나누는 것이 남은 항목의 삭제를 뜻하지 않는다.

이 문서는 실행 범위다. 완료 증거는 제품별 실행 기록에 둔다. `구현됨`, `검증됨`, `출시 가능`을 구분한다. 과거 로드맵의 미체크 항목은 현재 코드와 대조하기 전까지 `재점검` 상태다. 과거 기록에 적힌 줄 수·명령 수·완료 주장은 현재 구현 상태의 증거로 사용하지 않는다.

## 현재 실행 상태 — 2026-09-13

사용자가 1–3단계 완료까지 지속 진행하도록 요청했다. 범위와 외부 의존 조건은 아래 정의를 유지한다.

| 단위 | 상태 | 근거/다음 작업 |
| --- | --- | --- |
| S3-a | 검증됨 | Alt 드래그 복사, Shift 다중 선택·공통 속성, 여러 장의 삭제·복제·방향키 이동. 실행 취소·재열기 확인 |
| S3-b | 범위별 검증 | 새 자료의 한글 조합·공백·삭제·서식·붙여넣기, 기존 작성/객체 도구 검사 통과 |
| S4 | 범위별 검증 | 테마·마스터·레이아웃·발표·모션·미디어 검사. 발표 이동 수정 후 42개 통과 |
| S5 | 구현·검증 | JSON 교환, 인쇄/PDF 미리보기. 출력 3개 검사 및 실제 PDF 확인. PPTX는 교환 명세 참조 |
| Site T1–T3 | 범위별 검증 | 자동 저장·충돌 복구·최종 입력·출력 연결. 인수 검사 281개 통과, 시간 초과 1개 단독 재검사 통과 |
| 공통 통합 | 구현·검증 | 통합 자료함·제품 이동·전역 주소·검색·휴지통·참조·사본·이전. 통합 흐름 11개 및 저장 단위 12개 통과 |

S3-a 한계: 여러 장의 선택은 Shift 클릭으로 구성하고 공통 속성과 명령을 적용한다. 장을 가로지르는 마우스 범위 선택·동시 드래그 리사이즈는 추가 확장이다. 장을 가로지르는 그룹·쌓기·연결선 생성은 거부한다. 연결선 복사는 연결 대상이 함께 선택된 경우에 지원한다.

## 1. Slides 기본 제품 마감 — 현재

| 단위 | 구현·검증 범위 | 완료 기준 |
| --- | --- | --- |
| S3-a 캔버스 | 장 사이 객체 복사, 여러 장의 객체 동시 선택과 공통 서식. 기존 자유 배치·이동 유지 | 대상 장·좌표·선택·속성이 일치하며 취소, undo/redo, 저장/재열기로 검증 |
| S3-b 작성 | 한글 조합·삭제·붙여넣기·글자/문단 서식, 슬라이드 추가·복제·순서 변경, 그림·도형·표·그룹·레이어 | 새 자료에서 작성 흐름을 끝내고 데이터 손실 없이 다시 열기 |
| S4-a 디자인 | 테마·마스터·레이아웃·템플릿, 개별 덮어쓰기, 기존 자산/컴포넌트 도구 | 전체 테마 변경과 개별 서식 보존을 함께 검증. 레이아웃 변경 시 콘텐츠 보존 |
| S4-b 발표 | 발표 시작/종료, 이동, 발표자 노트·화면, 기존 전환·객체 모션·미디어 도구 | 실제 자료로 발표하고 편집기로 복귀. 확대·이동 후에도 입력 대상 유지 |
| S5 교환 | 기존 파일 저장/열기, 인쇄·출력, PPTX 최소 지원 범위 설계 및 결정 | 지원 형식·보존 항목·제한을 명시하고 실제 출력물 확인. JSON을 PPTX 지원으로 표시하지 않음 |

이미 있는 기능은 새로 만들지 않고 제품 흐름을 검증하며 결함을 수정한다. PPTX는 S5에서 가져오기/내보내기 방향, 지원 객체와 손실 안내를 결정한다. 결정 전에는 기본 PPTX조차 완료나 확정 범위로 표시하지 않는다.

## 2. Site 기본 제품 마감

| 단위 | 구현·검증 범위 | 완료 기준 |
| --- | --- | --- |
| T1 작성 | 페이지·탐색, 반응형 폭, 객체 배치·선택·속성, 텍스트·그림 | 실제 다중 페이지 사이트를 작성하고 각 화면 폭에서 확인 |
| T2 재사용·콘텐츠 | 컴포넌트·인스턴스, CMS·바인딩, 항목 Drawer, 미디어·웹폰트 | 원본/인스턴스·데이터 변경이 의도한 곳에만 반영되고 재열기 후 유지 |
| T3 저장·출력 | 자동 저장·복구·문서 전환, HTML/ZIP 출력, SEO·게시 미리보기 | 마지막 입력을 포함한 결과물을 열고 링크·자산·반응형 결과 확인 |
| T4 게시·폼 | 실제 호스팅 게시, 사용자 도메인 연결, 폼 수신과 제출 목록 | 통합 서비스 단계와 연결해 게시→접속→제출→조회 흐름 검증 |

T1–T3의 기존 구현을 먼저 인수 점검한다. T4는 서버·권한·호스팅이 필요하므로 4–5단계와 함께 마감한다. 정적 파일 다운로드만으로 게시 완료를 선언하지 않는다.

## 3. 공통 모듈과 통합 작업 공간

- 네 제품의 메뉴·툴바·속성·포털·아이콘·포커스 규칙을 공통 패키지에서 정리한다.
- 입력 소유권, 중첩 편집기, 선택·삭제·클립보드·undo, 확대 좌표의 실제 결함을 수정한다.
- 제품별 생성/열기/저장/닫기 계약과 전역 문서 ID를 연결한다. 제품의 런타임 노드 ID는 서비스 문서 ID와 구분한다.
- 같은 자료함에서 제품별 생성·열기, 검색, 최근 자료·즐겨찾기·휴지통·복원을 제공한다.
- 기존 로컬 자료의 이전은 사본·백업·복원을 먼저 검증한다.
- 제품 간 링크·참조·사본을 구분한다. Note 콘텐츠의 Site 사용과 Word/Slides 자료 연결을 검증한다. 모든 형식의 무손실 변환은 별도 범위다.

완료 기준: 한 작업 공간에서 네 제품을 오가며 마지막 입력과 문서 정체성이 유지된다. 앱 소스를 복사하지 않고 제품 패키지를 연결한다.

## 4. 팀 서비스와 협업

- 계정·팀·초대, 문서 소유권, 읽기/편집 권한, 권한 회수.
- 서버 저장·버전·복구, 실패 재시도, 충돌 처리, 첨부파일 수명 관리.
- 문서 공유와 제품 간 참조의 권한 검사. 공개 게시와 팀 내부 문서 권한 분리.
- 공동 편집의 동시 입력·삭제·실행 취소·재접속 계약. 한 제품에서 먼저 검증한 뒤 네 제품으로 확대.
- 실제 사이트 게시와 폼 수신을 서버·권한에 연결.

완료 기준: 다른 두 계정·브라우저에서 권한, 공유, 동시 수정, 연결 끊김과 복구를 확인한다. 로컬 자동 저장이나 같은 화면의 커서 표시만으로 협업 완료를 선언하지 않는다.

플랫폼 설계 기준은 OIDC·PostgreSQL·S3 호환 저장소, snapshot revision 검사와 별도 공동 편집 계약이다. 공급자·지원 버전·파일 제한·보관 정책은 WP-05의 실행 예제와 운영 조건으로 확정한다. 계정 접근, DNS, 유료 인프라 선택 등 외부 조건이 필요한 작업은 그 조건을 명시한다.

## 5. 첫 서비스 출시 검증

- 네 제품의 핵심 작성→저장→재열기→공유/출력 흐름과 데이터 복구.
- 공통 타입·빌드 실패 해결, 배포 대상 회귀 검사.
- 데스크톱 브라우저·실제 한글 입력기·키보드 조작·기본 접근성 확인. 접근성은 현재 기능 개발 뒤로 미룬 상태이며 출시 시점에 다시 점검한다.
- 긴 문서·큰 덱·미디어의 성능 기준 수립과 측정. 모바일 편집 지원 범위 명시.
- 서버 권한 검사, 백업 복원, 오류 관측, 배포와 되돌리기 절차.
- wonffice.com 연결 후 실제 사용자 환경에서 주요 흐름 검증.

완료 기준: 네 제품을 가진 통합 팀 서비스의 첫 출시. MS Office 전체 기능 호환이나 회사의 모든 업무 지원을 뜻하지 않는다.

## 6. 후속 기능과 기술 과제 — 목록 유지

| 영역 | 남은 범위 | 처리 원칙 |
| --- | --- | --- |
| Note | 문서 간·양방향 DB 관계, 확장 수식·교환, 고급 첨부 관리 | 기본 제품 단계 마감과 구분해 후속 명세화. 데이터 보호에 필요한 첨부 수명 관리는 4단계 |
| Word | 고급 DOCX/필드·캡션 참조 교환, 연속 구역·구역 병합, 고급 검토, 복합 표·페이지 나눔 | 사용자 요청으로 표 확장은 보류. 기존 입력·저장·출력 결함은 우선 수정 |
| Slides | 고급 PPTX 충실도, 차트 데이터, 추가 모션·영상 출력, 대규모 덱 최적화 | 기존 발표·모션 점검과 새 고급 기능 개발을 구분 |
| 공통 엔진 | DOM/React 선택 중복, 키맵 이주·읽기 전용 가드, 비형제 범위 선택, 전역 리스너, 좌표 변환, Site 셀 선택 | 과거 미완료 목록을 현재 코드와 재대조. 실제 결함은 해당 제품 단계에서 해결 |
| 라이브러리·플랫폼 | 순수 JS/React 사용 계약, 제품 패키지 연결, 추가 프레임워크, 서버 렌더링·별도 Canvas 텍스트 처리 | 통합에 필요한 계약은 3단계. 추가 런타임은 지원 대상과 수요를 정한 뒤 개발 |
| 새 제품 | 스프레드시트 등 회사 업무를 위한 추가 제품 | 현재 로드맵에 방향은 있으나 전체 기능 명세는 없음. 출시 순서와 최소 업무 시나리오부터 정의 |

후속 항목을 첫 출시에서 제외했다고 완료 처리하지 않는다. 단순 코드 중복 제거와 별도 렌더러 연구 때문에 현재 제품 마감을 무기한 늦추지 않는다.

## 진행 기록 규칙

각 단위에 `미착수 / 진행 / 구현됨 / 검증됨 / 외부 조건 대기 / 후속` 상태를 기록한다. 완료에는 코드·검사 결과·실제 화면 확인·남은 제한을 연결한다. 검증되지 않은 기존 기능은 구현 여부와 별개로 점검 대상으로 남긴다.

1–3단계의 정의된 로컬 기본 제품 범위는 마감했다. [통합 실행 기록](../../.dev/plans/office-workspace/brief.md)에 증거와 제한을 기록했다. 다음 작업은 **4단계 팀 서비스의 계정·서버 저장·권한 계약**이다. 출력 범위는 [Slides 교환 명세](slides-exchange.md)에 기록한다. 이후 팀 서비스 → 출시 검증 순서다. 제품 사용을 막는 입력·저장 결함은 순서와 관계없이 먼저 수정한다.
