# Wonffice 통합 작업 공간

1–3단계의 로컬 기본 제품 범위를 연결했다. 계정·팀·서버 저장·권한·공동 편집·실제 게시는 4–5단계다. 로컬 통합을 출시 완료로 표시하지 않는다.

## 구현 위치

- `packages/office-workspace`: 제품 레지스트리, 파일 검증, 자료함, 검색, 폴더, 즐겨찾기, 휴지통, 참조, 사본, 백업/이전.
- `packages/shared/src/document-save`: 조건부 저장 큐, 저장 세션, 제품 이동 전 입력 반영 계약, 제품 보관함 백업.
- `packages/office-editor-ui`: 공통 최근 자료/복구 UI와 파일 작업.
- 각 제품의 `./workspace` 진입점: 생성, 파일 읽기/쓰기, 스키마 검증. 렌더러를 마운트하지 않는다.
- `apps/office`: 하나의 주소에서 자료함과 네 제품을 제공하는 호스트. 기존 제품 앱의 진입점과 제품 패키지를 가져온다. 앱 소스를 복사하지 않는다.

실행: `pnpm dev:office`. 현재 개발 주소는 `http://localhost:5186/`다. 배포 빌드는 `pnpm build:office`다. [API 및 통합 가이드](../../packages/office-workspace/README.md)를 함께 읽는다.

## 화면과 편집 경계

자료함에서 Note, Word, Slides, Site를 만든다. 이름과 본문을 검색하고, 최근 자료·즐겨찾기·폴더·휴지통으로 찾는다. 자료를 열면 해당 제품의 기존 편집기가 열린다. 상단의 공통 탐색 도구로 자료함이나 연결된 원본 자료로 이동한다.

제품별 HTML 진입점은 같은 origin을 쓴다. 제품 전환은 전체 페이지 이동이다. 이 방식은 각 제품의 렌더러 레지스트리, 전역 입력 리스너, 스타일을 분리한다. 열린 편집기의 실행 취소 이력은 그 편집 세션에 속한다. 제품을 닫은 뒤의 영속 실행 취소 이력을 제공하는 것은 아니다.

공통 버튼·입력·선택·대화상자는 `office-ui`, 아이콘은 `office-icons`를 사용한다. 제품별 메뉴·툴바·속성 패널은 기존 `office-editor-ui`와 `office-controls` 경계를 유지한다. 공통 디자인 때문에 Note의 블록 편집과 Slides의 캔버스 배치를 같은 화면으로 강제하지 않는다.

## 문서 정체성과 저장

전역 주소는 **워크스페이스 ID + 제품 키 + 파일 ID**다. 모델의 런타임 node ID를 파일 ID로 쓰지 않는다. 이름·폴더·즐겨찾기·휴지통 변경은 파일 주소를 바꾸지 않는다.

한 origin에 하나의 로컬 작업 공간을 제공한다. 기존 제품별 IndexedDB 파일 저장소는 유지한다. 관리 정보에는 별도 revision을 적용한다. 관리 정보 변경으로 편집기 본문을 덮어쓰지 않는다. Note는 기존 페이지 계층의 즐겨찾기·휴지통 상태도 함께 반영한다. 상위 노트가 휴지통에 있으면 상위 노트를 먼저 복원한다.

Word·Slides·Site는 공통 `DocumentSession`을 사용한다. Note는 기존 중첩 세션 flush를 공통 이동 계약에 연결한다. 제품을 바꿀 때 다음 순서를 따른다.

1. 새 입력을 잠시 막고 중첩 편집기의 마지막 입력을 반영한다.
2. 조건부 저장과 충돌 초안 기록을 완료한다.
3. 편집 호스트와 파일 ID가 바뀌지 않았는지 확인한다.
4. 성공하면 이동한다. 실패하면 현재 화면을 유지하고 편집을 다시 허용한다.

다른 탭과 저장 revision이 충돌하면 원본을 유지하고 초안을 따로 보관한다. 저장 실패 시 새 문서나 템플릿으로 교체하지 않는다. 없는 파일과 휴지통 파일의 직접 주소는 오류를 표시하며 샘플로 대체하지 않는다.

제품별 최근 자료와 Word 보관함은 통합 작업 공간의 휴지통 자료를 일반 열기 목록에서 제외한다. 열기 직전에도 휴지통 상태를 다시 확인한다. 다른 탭에서 목록을 연 뒤 자료를 휴지통으로 옮긴 경우, 오류는 열려던 자료의 이름과 복원 경로를 알린다. 현재 편집 중인 자료의 저장 상태와 주소는 유지한다. 일시적인 읽기 실패는 같은 행에서 다시 시도하며 대상 ID를 바꾸지 않는다. 제품별 전체 백업에는 휴지통 자료도 계속 포함한다.

## 참조, 사본, 재사용

- **원본 참조**: 다른 제품의 원본 파일을 연다. 이름 변경 뒤에도 ID로 연결된다. 원본이 없거나 휴지통에 있으면 사용할 수 없음을 표시한다.
- **독립 사본**: 새 파일 ID를 만든다. 이후 원본 변경을 자동 반영하지 않는다.
- **Note → Site**: Note 본문을 새 Site 본문으로 복사하고 원본 자료 참조를 남긴다. 지원하지 않는 블록이나 Note 페이지 참조가 있으면 쓰기 전에 중단한다. 실시간 동기화 임베드는 아니다.

Word–Slides 참조와 Note–Site 본문 복사를 검증했다. 모든 제품 간 무손실 변환, 첨부 자산의 서버 수명 관리, 참조 권한 검사는 후속 범위다.

## 기존 자료 이전과 복구

다른 개발 포트는 서로 다른 브라우저 저장소다. 기존 주소의 자료는 해당 제품의 보관함 백업 또는 JSON 내보내기를 사용하고, 통합 자료함의 **백업 및 가져오기**에서 읽는다. 원래 저장소는 지우지 않는다.

지원 입력: Note·Word·Slides·Site JSON, 기존 Note 전체 보관함 백업, 제품별 보관함 백업, Wonffice 전체 백업. 전체 백업에는 휴지통 자료와 복구 초안도 포함한다. 외부 URL의 자산은 별도로 남을 수 있다.

복원은 모든 파일을 먼저 검증한 뒤 새 ID의 사본을 쓴다. 함께 복원한 Note 페이지 및 작업 공간 참조는 새 ID로 연결한다. 다중 제품의 저장소 전체가 하나의 트랜잭션은 아니다. 도중 저장이 실패하면 이미 쓴 사본 수를 표시한다. 기존 파일과 백업 원본은 유지한다.

## 검증과 남은 범위

통합 브라우저 9개 검사, 실제 백업 다운로드/복원 1개, Slides 편집 후 이름 유지 1개가 각각 통과했다. 공통 저장·이동 단위 12개도 통과했다. 통합 호스트 타입 검사와 네 제품을 포함한 생산 빌드가 통과했다. [실행 기록](../../.dev/plans/office-workspace/brief.md)에 명령, 결과, 실제 화면 확인을 기록한다.

현재 결과는 데스크톱 로컬 기본 제품이다. 서버 권한, 공유, 실시간 공동 편집, Site 실제 게시·도메인·폼 수신, 출시 수준의 성능·접근성·실기기 검증은 4–5단계다. 추가 프레임워크와 고급 형식 교환은 후속 범위를 유지한다.
