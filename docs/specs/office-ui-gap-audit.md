# 공통 UI 추가 범위 점검

점검일: 2026-09-14. 상태: 현재 데스크톱 기본 UI 정비 1차 마감. 아래 초기 근거 표와 최신 적용 기록을 함께 확인한다.

검증 범위: 데스크톱 화면을 우선한다. 사용자 요청에 따라 모바일 화면 설계와 크기별 검사는 후속 단계로 미룬다.

2026-09-14 다음 패키지 진행: office-ui 기본 범위의 1차 마감은 유지한다. office-editor-ui usePropertyCommand의 편집기·문서·선택 변경 보호를 보강하고 Slides·Site에서 검증했다. 이후 상태는 [편집 UI 공통화](office-editor-ui-consolidation.md)에서 추적한다.

2026-09-14 색상 형식 보완: 공통 ColorPicker에서 HEX·RGB(A)·HSL·HSB·OKHSL을 선택하고 각 채널을 편집한다. 형식 변경 시 색상과 문서 상태를 유지하며, 변환은 Color.js로 처리한다. 저장은 기존 sRGB HEX/RGBA 계약을 따른다. 단위 검사 7개·브라우저 검사 6개, 공통 UI 타입 검사와 Office 빌드 통과. 넓은 색역 보존·추가 색 공간은 이번 범위가 아니다.

2026-09-14 혼합 설정 위치 수정: 혼합 모드는 색 자체의 속성이 아니므로 Slides의 각 채우기 행 아래로 옮겼다. StackRow.details는 팝업 밖의 상시 설정을 표시한다. 팝업에는 색 또는 채우기 내용 편집을 두며, ColorPicker API에 혼합 모드를 추가하지 않는다. 브라우저 검사 5개, office-ui·Slides 타입 검사, Office 빌드 통과.

2026-09-14 기본 UI 마감: 이동 패널 안의 ColorPicker가 가용 너비를 채우도록 수정했다. 색상·코드·혼합 입력의 오른쪽 경계를 맞추고, 스크롤 본문에 손잡이 공간을 확보했다. StackRow 편집 제목에 위·아래 순서 버튼을 추가했다. useStackOrder는 명시적 이동과 드래그를 같은 연산으로 처리하며 높이가 다른 행의 실제 경계를 사용한다. Slides 효과 수치는 가로·세로·흐림·확산 이름과 pt 단위를 표시한다. 데스크톱 브라우저 검사 6개, office-ui·Slides 타입 검사(기존 미사용 항목 제외), Office 빌드가 통과했다.

이번 마감은 현재 제품에 필요한 기본 컴포넌트 정비 범위다. 모든 제품 UI와 모든 향후 컴포넌트의 완료를 뜻하지 않는다. 다음 작업은 [편집 UI 공통화](office-editor-ui-consolidation.md)의 순서로 진행한다.

2026-09-14 이동 가능한 색상 창: StackRow의 floatingEditor와 ColorField에 공통 useMovablePanel을 연결했다. 초기 위치는 속성 패널 옆이고, 제목 드래그로 옮긴 뒤에는 해당 위치를 유지한다. 창 경계를 제한하며 긴 내용만 내부에서 스크롤한다. DOM·테마·fieldset 소속은 유지하면서 최상위 영역에 표시해 속성 패널의 overflow에 잘리지 않게 했다. 드래그 취소·색상 입력·포커스 복귀·캔버스 축 연동·Site 회귀를 포함한 데스크톱 브라우저 검사 11개가 통과했다.

2026-09-14 그라디언트·효과 편집: StackRow의 공통 제목·닫기·포커스 계약을 Slides에 연결했다. 색 지점의 키보드 선택, 정렬 후 선택 유지, 패널 드래그의 로컬 미리보기·한 번 적용·취소를 추가했다. 패널 키 입력은 캔버스에서 처리하지 않는다. Site는 기존 공통 색상·숫자 입력을 유지하고 선형·원형 이름을 맞췄다. 브라우저 검사 22개와 공통 UI·Slides 타입 검사, Office 빌드가 통과했다. Site의 배경은 시작·끝 색 모델이고 Slides는 다중 채우기·색 지점 목록 모델이다. 표시 컴포넌트는 공유하지만 두 모델을 하나로 합치지 않는다.

2026-09-14 색상·숫자 입력: ColorField의 키보드 열기를 색상 코드 포커스에 연결하고, Tab으로 벗어나면 팝업을 닫는다. Escape는 버튼으로 돌아간다. 긴 색상 이름은 행을 늘리지 않고 줄여 표시한다. NumberField에 방향키·Shift·Alt 조정을 추가했으며 확정 전 문서 변경과 중복 이력 생성을 막는다. 브라우저 검사 10개와 단위 검사 12개, 관련 타입 검사와 Office 빌드가 통과했다. 검사는 데스크톱에서만 실행했다.

2026-09-14 Slides 속성 실행: office-editor-ui의 usePropertyCommand를 Site와 Slides가 공유한다. Slides 속성의 처리 중 입력 제한, 명령 거부·예외 안내, 원래 대상과 값으로 재시도를 연결했다. 선택·슬라이드·문서·단위 변경 시 이전 오류와 초안을 지운다. 다중 선택·cm 변환·잠금 해제·모서리·컴포넌트·모션과 Site 회귀를 포함한 데스크톱 브라우저 검사 12개, 관련 타입 검사와 Office 빌드가 통과했다. 실제 통합 Slides에서 너비 10cm 적용을 확인했다.

2026-09-14 그림 교체 이력: Site insertAsset의 applyTo로 자산 추가와 대상 참조 변경을 한 트랜잭션으로 묶었다. picture src·mediaVideo src/poster·사이트 icon만 허용한다. 잘못된 대상과 다른 문서의 노드는 거부한다. 단위 검사 27개와 데스크톱 브라우저 검사 3개, Site 타입 검사와 Office 빌드가 통과했다. 그림 교체의 실행 취소·다시 실행과 선택 유지가 확인됐다. 새 그림 블록 생성까지 포함하는 드롭 이력 통합은 별도 후속 범위다.

2026-09-14 Site 속성 실행: 공통 run 경로에 명령 큐와 StatusIndicator·StatusNotice를 연결했다. 실패한 명령·값은 같은 대상에서 재시도하며, 대상 변경 시 이전 오류·초안을 지운다. 한 번의 위치 변경이 보내는 여러 명령도 순서대로 실행한다. insertAsset의 선택 적용·선택 이력 저장을 끄고 그림 교체 후 선택이 새 자산으로 이동하는 문제를 수정했다. 데스크톱 브라우저 검사 5개, Site 타입 검사와 Office 빌드가 통과했다. 이미지 추가·대상 적용의 단일 실행 취소는 아직 남아 있다.

2026-09-14 속성 패널 점검: Slides·Site는 이미 PropertySheet·PropertyNumber·PropertyEmpty를 사용한다. 다만 여러 속성 명령이 실행 결과를 기다리지 않는다. 이번에는 Site picture 행의 별도 파일 입력을 공통 FilePick·FileItem으로, 자산 목록을 SearchSelect로 교체했다. StatusIndicator·StatusNotice로 처리·실패·재시도를 제공한다. 그림 처리 중 중복 입력과 편집 문서 변경을 확인한다. Site 타입 검사와 Office 빌드, 데스크톱 브라우저 검사 3개가 통과했다. 일반 속성 명령의 실패 표시와 그림 교체 후 선택 유지·단일 실행 취소는 남아 있다.

2026-09-14 통합 자료 연결·백업 입력: 자료 관리에 SearchSelect를 적용했다. 이름·제품·폴더 검색, 방향키·Enter 선택, Escape로 검색만 닫기를 제공한다. 자기 자신·휴지통·이미 연결한 자료는 제외한다. 백업 입력은 FilePick·FileItem을 사용한다. 복원 중 파일 바꾸기·제거·닫기를 막고, 실패 시 선택을 유지하며 성공 후 비운다. 기존 연결·독립 사본 복원 계약을 유지한다. JSON 구문 오류는 한국어 재선택 안내로 표시한다.

2026-09-14 Word 문단 설정·통합 자료함 상태: Word 문단 간격·테두리·페이지 설정의 초안·선택·비동기 적용 처리를 useFormattingDialog로 묶었다. 실패 시 값을 유지하고 처리 중 중복 실행·닫기를 막는다. 변경 없이 확인하면 명령을 실행하지 않는다. 문단 간격 체크박스와 테두리 사전 설정 버튼은 공통 컴포넌트를 사용하고, 테두리 창은 390px에서 세로로 배치한다. 통합 자료함의 읽기 실패·재시도·완료·빈 상태를 StatusNotice·StatusIndicator·EmptyState로 교체했다. 검색·필터 초기화와 즐겨찾기·최근 자료·휴지통의 빈 상태를 구분한다. Word 15개·통합 자료함 3개로 브라우저 검사 18개가 범위별 통과했다. Word·office-workspace 타입 검사(기존 미사용 항목 제외)와 Office 빌드가 통과했다. 기존 통합 Word의 테두리 창과 실제 자료함 검색에서 확인했다. 다음은 통합 자료 관리의 연결할 자료 선택과 백업 파일 입력을 공통 UI에 연결하는 작업이다.

2026-09-14 Word 페이지 설정·보관함: 페이지 설정의 체크박스와 유효성·실패 안내를 공통 UI로 교체했다. 설정 적용을 기다리며, 실패 시 초안을 유지하고 재시도할 수 있다. 대화상자를 열 때 선택한 구역을 보존하고 처리 중 중복 적용·닫기를 막는다. 390px에서는 여백 입력을 한 열로 배치한다. Word 보관함은 공통 NavigationItem·TextField·EmptyState·StatusIndicator를 사용한다. 제목 검색·검색 지우기·읽기 실패 재시도를 추가했다. 기존 6개·추가 3개로 브라우저 검사 9개가 범위별 통과했다. Word 타입 검사(기존 미사용 항목 제외)와 Office 빌드가 통과했다. 기존 통합 Word 탭에서 페이지 설정과 보관함 검색을 확인했다. 다음은 Word 문단 간격·테두리 대화상자의 적용·취소·오류 처리와 통합 자료함의 빈 상태 점검이다.

2026-09-14 Word 찾기 공통화: 입력·체크박스·패널 제목·작업 버튼·상태 안내를 office-ui로 교체했다. SearchResultNavigation을 추가해 Note와 Word의 결과 개수·이전/다음·빈 상태를 통일했다. Word 찾기 패널은 문서 스크롤 중에도 유지되며 작은 화면에서 현재 결과를 가리지 않도록 이동한다. 한글 조합 중 Enter·Escape, 결과 없음, 바꾸기 실패·재시도, 전체 바꾸기 실행 취소, 메뉴 연결을 확인했다. Word 11개·Note 4개 브라우저 검사가 범위별 통과했다. Word·office-ui 타입 검사(기존 미사용 항목 제외)와 Office 빌드가 통과했다. 다음은 Word 페이지 설정과 자료함의 자체 입력·오류·빈 상태 점검이다.

2026-09-14 다중행 입력: TextAreaField의 확정·취소·오류·대기 계약을 추가하고 Site longText 표·Drawer에 연결했다. 공백 보존과 텍스트 붙여넣기 분리, Drawer Escape 취소를 검증했다. 브라우저 12개·데이터 단위 20개가 통과했다. 다음은 Word 찾기의 입력·결과·빈 상태 점검이다.

2026-09-14 Note 보기 공통화: 필터·정렬 작업 행, 보기 이름, 속성 체크박스, 레이아웃 버튼을 공통 컴포넌트로 바꿨다. 추가한 `FloatingPanelFooter`는 표시만 담당한다. Note 5개·갤러리 및 버튼 4개 브라우저 검사가 통과했다. 다음은 TextAreaField의 확정·취소·오류 계약과 Site 긴 텍스트 셀이다.

2026-09-14 Site 명령 검색: 관리·페이지 메뉴를 공통 검색에 연결했다. 글 고치기 제한, 선택 복원, 문서 교체 검사, 키 입력 분리와 기존 출력 상태 연결을 확인했다. 검색 3개·출력 2개·제품 메뉴 1개의 브라우저 검사 및 Office 빌드가 통과했다. 기존 Site 타입 오류 3건은 남아 있다. 다음은 Note 필터·보기 설정의 공통 UI 적용 점검이다.

2026-09-14 Slides 명령 검색: 메뉴와 직접 실행하는 툴바 명령을 공통 검색에 연결했다. 현재 슬라이드·객체 선택을 복원하며, 실행 불가 이유와 최근 명령을 표시한다. 파일 선택과 색·글꼴 값 입력은 제외했다. Word·Slides 공통 검색 버튼을 추가했다. 브라우저 7개와 모델 단위 검사 3개가 통과했다. 다음은 Site 명령 검색 연결이다.

2026-09-14 DOCX·HTML 출력: Word DOCX의 변환·다운로드 실패와 재시도, Site HTML·ZIP 출력 상태를 공통 UI에 연결했다. 여러 작업 안내는 `TaskStatusRegion` 안에 쌓아 표시한다. 원본 보존, 실패 재시도, 중복 실행, 문서 교체, 작은 화면 겹침을 검사했다. 브라우저 7개와 공통 단위 검사 10개가 통과했다. 다음은 Slides 명령 검색 연결이다. 작업 실행 큐·작업 스레드 변환·실제 다운로드 완료 추적은 범위에 포함하지 않았다.

2026-09-14 Slides 파일 공통화: 별도 실행 코드를 공통 `FileActions`로 교체했다. 덱 저장 형식과 기존 교체 확인 순서는 유지한다. 확인 취소와 저장 실패를 구분하는 계약을 추가했다. Slides 8개·Word/Site 2개의 브라우저 검사와 공통 단위 검사 10개가 통과했다. 다음은 DOCX/HTML 출력 상태 연결이다.

2026-09-14 작업 상태 적용: `TaskStatus`와 공통 화면 하단 배치를 Word·Site JSON 파일 작업에 연결했다. 처리 중·완료·실패·취소, 다른 파일 선택과 출력 재시도를 제공한다. 임의 진행률이나 다운로드 완료 보장은 표시하지 않는다. 단위 검사 7개와 갤러리·Word·Site 브라우저 검사 3개가 통과했다. 다음은 별도 구현으로 남은 Slides 파일 UI의 공통화다. DOCX/HTML 출력과 여러 작업 큐는 남아 있다.

2026-09-14 명령 검색 적용: `CommandSearch`를 Word 헤더에 연결했다. 기존 메뉴와 기본 서식 18개를 검색하고, 문서 선택 복원·실행 가능 상태·조합 입력 보호·최근 명령을 제공한다. 후속 Dialog는 검색창 종료 후 연다. 검색 2개·Word 1개·기존 모달 5개의 브라우저 검사가 통과했다. 전체 리본 명령과 Slides·Site·Note 연결은 남아 있다. 다음 구현은 실제 가져오기·출력 흐름의 장시간 작업 상태와 완료 안내다.

2026-09-14 파일·미디어 적용: `FileDropZone`·`FileItem`을 Word 그림 삽입에, `MediaSelect`를 Site 이미지 데이터 필드에 연결했다. 선택·드롭 검증, 재선택, 처리 실패·비활성, 문서 이미지 미리보기와 검색을 제공한다. 갤러리·Word·Site 브라우저 검사 5개가 통과했다. 다음은 명령 검색 UI다. 다중 업로드와 서버 자산 관리는 남아 있다.

2026-09-14 검색·태그 적용: `SearchSelect`·`SelectionTag`를 Note 관계 선택, Office 편집기 원본 자료 선택, Site 다중 선택에 연결했다. 공통 검색·키보드·단일/다중 확정·태그 제거를 사용하며 제품 저장 로직은 유지한다. 공통 모션도 적용했다. 갤러리와 세 사용처의 브라우저 검사 6개, Note UI 단위 검사 10개가 통과했다. 다음 구현은 파일·미디어 선택이다. 원격 검색·가상 목록·모든 기존 Choice 교체는 완료 범위에 포함하지 않는다.

후속 적용: 우선순위 0의 기본 프레임·핸들 표시를 세 제품에 적용했다. 표 경계 토큰·정렬 가이드·공통 크기 표시, Word·Slides 작은 객체의 핸들 축소, Site 고정 크기 표시의 확대·이동 추적을 추가했다. 상세 범위와 검증은 [디자인 시스템 기준](../../packages/office-ui/DESIGN_SYSTEM.md)의 선택 도구 절을 따른다. 모든 객체 종류와 회전·연결점의 충돌 검증은 남아 있다. 다음 제품 적용은 검색형 선택 목록과 태그다.

## 판단

기본 UI보다 복합 입력과 작업 흐름의 공통화가 더 필요하다. 새 컴포넌트 수를 늘리는 것을 목표로 삼지 않는다. 기존 컴포넌트가 있으면 먼저 실제 제품에 적용한다.

점검 범위는 office-ui·office-editor-ui·office-controls의 공개 API, Note·Word·Slides·Site의 사용처, 직전 브라우저 검사에서 만든 제품 비교 이미지다. 이번 점검에서는 코드를 변경하거나 새 기능을 실행하지 않았다. 기본 비교 이미지는 빈 문서에 가까우므로 복합 편집 화면 전체를 검증한 근거로 사용하지 않는다.

## 이미 있는 것

- 버튼·토글·숫자·텍스트·색상·단일 선택 입력.
- 메뉴·툴팁·팝업·Dialog·Drawer·SidePeek.
- 공통 헤더·제품 메뉴·작은 화면 패널·도구 넘침 처리.
- 속성 그룹·혼합 값·레이어 행·데이터 표 표시·빈 상태.
- 저장 상태·오류 안내, 문맥 도구와 선택 복원.

별도의 새 버튼 체계, 새 Drawer, 새 리본을 만들 필요는 없다. DataTable은 표시 컴포넌트이며 완전한 데이터 그리드 동작을 제공하는 것으로 취급하지 않는다.

## 먼저 추가할 공통 UI

선택 도구를 앞선 목록에서 누락해 우선순위 0으로 보완했다. 객체 선택 테두리·핸들·가이드의 공통 시각 규격을 먼저 정한다. 문맥 툴바만으로 선택 도구 전체를 정의했다고 판단하지 않는다.

| 순서 | 후보 | 현재 근거 | 첫 적용 위치 | 완료 기준 |
| --- | --- | --- | --- | --- |
| 0 | 객체 선택 프레임·조작 핸들·가이드 | Word·Slides·Site가 별도 오버레이와 스타일을 사용한다. Word 핸들은 자체 9px 크기와 고정 색을 사용한다. | Word 이미지, Slides 도형, Site 블록 비교 | 상태·색·두께·표시 크기와 클릭 영역, 확대율·스크롤·경계 잘림, 선택과 조작의 입력 소유권, 취소·undo 검증 |
| 1 | 검색형 선택 목록 | ChoiceSelect에는 검색 입력이 없다. Note 관계 선택은 별도 검색창·목록을 작성한다. 통합 참조 선택은 전체 자료를 Choice에 나열한다. | Note 관계 선택, 통합 Office의 원본 자료 선택 | 검색·방향키·Enter·Escape, 현재 값 표시, 검색 결과 없음, 긴 이름, 조합 입력, 중첩 팝업 포커스 확인 |
| 2 | 다중 선택과 제거 가능한 태그 | Site choices는 모든 옵션을 버튼으로 나열한다. Note 관계 태그는 자체 열기·제거 버튼을 사용한다. | Note 관계, Site 다중 선택 | 선택 개수·검색·개별 제거·전체 해제·읽기 전용을 구분. 항목 열기와 제거를 분리. 저장 실패 때 호스트 값과 일치 |
| 3 | 파일 놓기 영역·파일 항목·미디어 선택 목록 | FilePick은 파일 하나를 고르는 버튼이다. Site 이미지 값은 이름 목록에서 선택한다. 파일 가져오기와 이미지 선택 화면은 제품별로 구성한다. | Site 이미지 선택, Word 이미지 삽입 | 이름·미리보기·크기·제한 오류·처리 중 상태 표시. 동일 파일 재선택. 파일 클릭 선택과 드롭 경로 일치 |
| 4 | 검색으로 명령 찾기 | ToolbarOverflow는 기존 도구 그룹으로 이동한다. 검색 가능한 전체 명령 목록과는 다르다. SlashMenu는 본문 삽입을 위한 편집기 UI다. | Word 명령 찾기, 이후 Slides | 현재 문맥에서 실행할 수 있는 명령만 정확히 연결. 단축키 표시. 편집 선택 보존. 실행 불가 이유와 최근 명령 처리 |
| 5 | 장시간 작업 상태와 완료 알림 | StatusIndicator·StatusNotice는 있다. 가져오기·출력·복구의 진행 항목과 완료 안내를 묶는 공통 UI는 공개 API에 없다. | 파일 가져오기·출력·백업 복구 | 진행률이 없으면 임의 숫자를 표시하지 않음. 실제 지원되는 취소·재시도만 노출. 저장 실패는 자동으로 사라지는 알림에만 두지 않음 |

1과 2는 같은 검색 목록 기반을 공유하되 단일 선택과 다중 선택의 확정 방식을 명시한다. 예를 들어 단일 선택은 선택 후 닫고, 다중 선택은 계속 고를 수 있게 유지한다. 서로 다른 동작을 옵션 이름 없이 암묵적으로 섞지 않는다.

미디어 선택 목록은 파일을 서버에 올리는 기능과 구분한다. 먼저 현재 문서의 로컬 자산을 선택한다. 업로드·권한·보관 정책은 서비스 계층이 담당한다.

## 신규 개발보다 기존 UI 적용이 먼저인 곳

| 위치 | 확인한 차이 | 작업 |
| --- | --- | --- |
| Note 데이터베이스 보기 설정 | 자체 텍스트 입력·체크박스 | TextField·PropertyToggle을 적용하고 현재 확정·취소 동작 유지 |
| Note 필터·정렬 팝업 | 공통 FloatingSurface 위에 자체 제목·작업 행·이동/삭제 버튼 | 공통 헤더·버튼·간격 사용. 필터 모델은 제품에 유지 |
| Site 긴 텍스트 셀 | 자체 textarea와 blur 확정 | 공통 다중행 입력의 확정·취소 계약을 먼저 보강한 뒤 연결 |
| Word 찾기·페이지 설정 | 일부 자체 입력·체크박스 | 공통 필드로 연결. 찾기 결과와 문서 선택 보존 |
| 통합 자료함 | 일부 오류·빈 상태를 일반 문단으로 표시 | 기존 StatusNotice·EmptyState 적용 |

네이티브 input이 있다는 이유만으로 결함으로 분류하지 않는다. 파일 입력처럼 브라우저 기능을 위한 숨은 요소와 문서 본문 렌더러는 교체 목록에서 제외한다.

## 후속 또는 조건부 추가

- **날짜 입력:** 현재 Note·Site는 TextField의 date 타입을 사용한다. 먼저 표시·빈 값·수동 입력 규칙을 통일한다. 날짜 범위·시간·시간대 요구가 정해지면 DatePicker를 추가한다.
- **숫자 슬라이더:** NumberField는 이미 드래그 조정을 지원한다. 범위를 한눈에 봐야 하는 불투명도·음량에서만 공통 Slider를 검토한다. 모든 숫자 입력에 추가하지 않는다.
- **필터·정렬 편집기:** Note의 구현을 첫 기준으로 삼는다. Site와 필요한 모델이 일치하는지 확인한 뒤 표시 행을 추출한다. 필터 계산 로직을 office-ui로 옮기지 않는다.
- **공유·팀 UI:** 멤버 선택, 권한 선택, 초대 상태, 공유 링크, 접근 거절, 동기화 충돌 상세가 필요하다. 로드맵 4단계의 인증·권한·서버 저장 계약과 함께 구현한다. UI만으로 공유가 완료된 것처럼 표시하지 않는다.

## 패키지 경계

- office-ui: 검색 목록·태그·파일 항목·상태 표시. 값과 callback만 받는다.
- office-controls: 명령 이름·검색어·단축키 등 제품 중립 선언. 새 필드가 필요할 때만 추가한다.
- office-editor-ui: 편집 선택 보존·명령 실행·활성 상태 연결.
- office-workspace 및 제품: 자료 검색, 관계 저장, 파일 처리, 권한, 재시도와 실행 취소.

각 후보는 갤러리의 상태 예시와 실제 사용처를 함께 구현한다. 두 번째 사용처에서 모양만 같고 저장 동작이 다르면 저장 로직까지 공통화하지 않는다.
