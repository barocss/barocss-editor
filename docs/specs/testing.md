# 검사 — 무엇을 단위로 묻고 무엇을 브라우저로 묻나

**한 줄로: 검사가 묻는 답을 *우리 코드* 가 정하면 단위, *브라우저* 가 정하면 e2e.**

기본값은 단위다. 단위로 못 잡는 것이 아니라 **단위가 없는 것**인 경우가 훨씬 많고, 이 저장소는
그 값을 여러 번 치렀다.

## 판단하는 질문

```
이 검사가 묻는 답을 누가 정하는가?
├─ 우리 코드 → 단위 (기본값)
└─ 브라우저 → e2e
```

| 브라우저가 정하는 것 | 우리가 정하는 것 |
|---|---|
| 클릭이 캐럿을 어디에 두나 — 히트테스트·줄바꿈 | 키 → 명령 (레지스트리) |
| 무엇이 보이나 — 레이아웃·겹침·스크롤 | 모델 연산과 그 역 |
| IME 가 무엇을 언제 보내나 | DOM ↔ 모델 자리 변환 (**jsdom 이면 충분**) |
| 초점이 어디로 가나 | 스키마 검증 |
| 네이티브 복사·붙여넣기·드래그 | 메뉴·툴바 모델, 무엇이 어느 목록에 있나 |

**`jsdom` 이 경계를 옮긴다.** 요소에 `keydown` 을 던지고 어느 리스너가 받는지 묻는 것, 범위를
세우고 모델 자리를 묻는 것, 채움 글자 뒤가 오프셋 0인지 묻는 것 — 전부 단위다. *DOM 을 만지니까
브라우저* 가 아니다. **레이아웃과 히트테스트가 필요할 때만** 브라우저다.

## e2e 에는 셋째 역할이 있다

*조립 검사* — 부품이 다 맞아서 **앱이 실제로 뜨는가**, 그리고 **우리가 물을 생각조차 못 한 것**.

사이트의 `/` 버그가 그것이었다: 슬래시 메뉴와 버블 툴바가 같이 떴고, 단위 검사가 **없었던 것이
아니라 의심을 안 했다.** 그 역할은 진짜이고, 그래서 앱 회차를 없애지 않는다.

## 그러나 앱 회차를 줄이라는 뜻도 아니다 — 쟀다

| 앱 | `test()` | 좌표·마우스 | IME |
|---|---|---|---|
| slide | 397 | **345** | 1 |
| site | 283 | **175** | 4 |
| word | 354 | 124 | **121** |
| note | 22 | 32 | 0 |

slides 는 그리기 도구라 대부분이 진짜 히트테스트이고, word 는 IME 가 121곳이다. **이 검사들은
정당하게 브라우저의 것이다.**

## 규칙: e2e 가 잡은 것은 **단위로 내려 적는다**

2026-09-05 회차에 e2e 가 잡은 것을 갈라 보면:

| e2e 가 잡은 것 | 단위로 되나 | 실제로 |
|---|---|---|
| site: `/` 에 떠 있는 표면 둘 | 된다 | 그때는 없었고, 지금 `boundary-inside-a-block` 이 있다 |
| word: 메뉴가 ⌘Z 를 안 가르침 | 된다 | **내려 적었다** — 4분 → 밀리초 |
| note: 인용문에서 Enter | **안 된다** — 짧은 줄 오른쪽 빈 곳 클릭이 히트테스트다 | e2e 로 남는다 |

**내려 적지 않으면 다음에 또 4분을 낸다.** 그리고 e2e 는 *증상* 을 주고 단위는 *원인* 을 준다:
`/` 버그의 증상은 브라우저가 줬고, 원인(접힌 캐럿이 어느 쪽으로 접히나)은 표로 된 단위 검사가 줬다.

## 회차를 돌리는 도구도 검사다

이 회차에 **가드가 자기가 막을 것을 못 보는 결함**이 코드가 아니라 **도구** 에서 네 번 나왔다:

1. 단위 요약 필터가 `2 failed | 479 passed | 3 skipped` 를 **걸러냈다** — 두 라운드 동안 *실패 0*
   이라고 말하며 빨간 상태로 커밋했다
2. e2e 스크립트 두 회차가 같은 로그를 **겹쳐 써서** `site` 줄이 통째로 사라졌다
3. 잠금이 디렉터리 하나여서 **내가 지웠고**, 개발 서버 둘이 포트를 다퉜다
4. 회차 **중에 소스를 고쳐서** vite 가 페이지를 새로 고쳤고, 5개 실패가 제품 결함처럼 보였다

그래서 도구가 스스로 센다: 실패 수를 세고, 앱 넷이 다 돌았는지 세고, 살아 있는 프로세스와 포트로
겹침을 막고, **시작과 끝의 작업 트리 해시를 비교해 달라졌으면 "이 회차는 무효"라고 적는다.**

**실패를 숨길 수 있는 필터로 초록을 선언하면 그 초록은 아무것도 뜻하지 않는다.**

## 새 검사를 놓는 순서

1. **단위부터 쓴다.** 답을 우리 코드가 정하면 여기서 끝난다.
2. 브라우저가 정하는 답이면 e2e 로 쓰되, **그 안에서 우리 코드가 정하는 부분은 따로 단위로** 쓴다.
3. e2e 가 무언가를 잡으면 **원인을 단위로 내려 적는다.** 증상만 고치고 지나가지 않는다.
4. 검사가 무엇을 세는지 **자기 프로세에 적는다** — 다음 사람이 그 숫자를 다시 재지 않도록.
