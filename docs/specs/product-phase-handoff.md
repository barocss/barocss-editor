# 제품 단계 전환 기준

기준일: 2026-09-13. 진행 순서는 **Note → 공통 모듈 점검 → Word → Slides → Site**다. 제품별 기본 편집 완성과 통합 서비스 출시는 별도 상태로 관리한다.

현재 주력은 **Slides**다. 사용자 결정에 따라 제품군을 먼저 확장한다. Word는 W6c-8까지의 기본 편집·검토·로컬 저장 및 지원 범위의 교환을 기준으로 다음 제품으로 넘어간다. 고급 DOCX SEQ/TOC·캡션 참조 교환은 후속 항목으로 옮긴다. Word 입력·저장 회귀는 계속 수정한다. 전체 Word 기능, 실제 OS IME, 전체 타입 검사 및 서비스 출시를 완료로 표시하지 않는다. 접근성·표 확장 보류는 유지한다. 이 결정이 아래 과거 기록의 “다음 작업”보다 우선한다.

최종 목표는 회사가 하나의 Office에서 업무를 수행하는 것이다. 진행 순서는 Slides → Site → 통합 서비스이며, 이후 제품도 같은 문서·권한·저장 계약 안에서 확장한다.

## Note: 데스크톱 로컬 편집 1차 마감

현재 범위는 문서/블록 작성, 서식·표·컬럼, 페이지 정리와 링크, 데이터베이스 보기·속성·관계/수식/롤업의 지원 범위, 셀 범위 붙여넣기, 본문 수식, 로컬 저장·충돌/복구·백업이다. 세부 구현과 범위별 근거는 [Note 진행 문서](../../.dev/plans/note-product-foundation/brief.md)에 있다.

이번 마감 점검은 단위332개, 주요 브라우저20개 시나리오를 대상으로 했다. 최초 브라우저 결과19/20이며, 메뉴 클릭 중 페이지 재로드로 중단된 블록 변환1건은 별도2회 재실행 모두 통과했다. 생산 빌드는 성공했다. 전체 브라우저 스위트가 한 번에 통과했다는 기록으로 바꾸지 않는다.

새 기능의 주력은 Word로 옮긴다. Note에서 발견되는 입력/저장 회귀는 계속 수정한다. 다음은 완료 처리하지 않는다.

- 제품 확장: 첨부파일 관리, 문서 간·양방향 DB 관계, 더 넓은 수식/교환 지원.
- 출시 검증: 모바일/터치, 접근성, 실제 OS IME, 긴 문서 성능 기준, 공유 타입 오류 해소.
- 서비스: 계정·팀·권한, 서버 저장/동기화, 공유·실시간 협업.

## Word: 기본 편집 기준으로 단계 전환

W1–W5f의 기존 구현을 이어받아 W5g의 빠른 키보드 선택/명령 대상 유지·Undo 분리와 리본 줄 간격을 수정·검증했다. 클립보드 도구와 권한 실패 시 대체 입력도 연결했다. 글자 서식 복사와 머리글·바닥글·페이지 번호 작성도 연결했다. 다음 페이지 구역 나누기와 목차 작성·자동 갱신도 연결했다. 표/이미지 상황별 크기·배치, 행·열 치수, 열 균등 분배와 비율 기반 그림 자르기도 연결했다. 셀 여백과 그림 대체 텍스트도 연결했다. 연속 구역·구역 병합과 고급 목차는 남아 있다. W6a에서 작성·변경 추적·저장/재열기·48행 표 인쇄를 연결해 검증했다. 한글 조합 반영 순서와 열 너비 지정 표의 높이 측정 오류를 수정했다. W6a 최종 Chromium 69개, Word 단위 599개와 공통 조합 경계 7개 시험 및 빌드가 통과했다. W6b-1에서 수식 팝업을 Note와 같은 공통 시각/LaTeX 편집 UI로 연결하고 적용·취소·Undo·자동완성을 검증했다. W6b-4에서 여러 줄 머리행의 병합 구조·서식·페이지 위치·인쇄를 검증했다. W6b-5에서 페이지에 들어가는 세로 병합 묶음의 경계와 하단 드래그를 검증했다. 다음은 표/수식 도구의 키보드 흐름과 상황별 리본 상태 점검이다. 고급 DOCX 보존 범위는 별도 검증이 필요하다. 페이지 설정의 단 수/간격 UI는 이미 있으므로 새로 구현할 대상으로 중복 기록하지 않는다.

완료 기준은 새 문서에서 작성·서식·객체 삽입·검토·저장/재열기·인쇄/교환까지 실제 작업을 끝내는 것이다. 버튼 존재나 명령 등록 수만으로 완료하지 않는다. [기능별 현황](word-toolbar-capabilities.md)과 [실행 기록](../../.dev/plans/word-product-foundation/brief.md)을 함께 갱신한다.

## 2026-09-09 — W6b-2: Word 본문 수식 편집

W6b-1의 다이얼로그 기본 결정을 확장했다. 기존 Word의 oMath/분수/슬롯 모델과 office-text 수식 렌더러를 유지한다. 수식 더블클릭 또는 삽입 → 본문 수식에서 math-editor 초안을 해당 위치에 연다. 빈 본문 커서에서도 같은 도구로 인라인 수식을 삽입한다. 기존 시각 편집/LaTeX 다이얼로그는 유지한다.

office-editor-ui의 MathInlineInput은 초안 입력, 자동완성 키보드, 조합 중 완료 방지와 적용/취소 UI를 맡는다. office-word의 useWordMathInplace는 임시 입력 영역과 Word 타깃을 연결한다. WordMathTarget/bridge/session은 원본 변경 검사, 구조 변환, 한 트랜잭션 적용과 수식 뒤 커서를 맡는다. Note의 tex 원자 모델을 Word에 복사하지 않는다. 입력 중 임시 DOM은 data-editor-input-owner 경계 안에서만 변경하고, 적용/취소 후 경계를 제거한다.

Enter는 자동완성이 열려 있으면 항목을 선택하고, 닫혀 있으면 수식을 적용한다. Esc는 자동완성을 먼저 닫고, 그 다음 초안을 취소한다. 외부 클릭은 초안을 먼저 적용한다. 빈 초안은 취소한다. 적용 후 Word 렌더러로 돌아오고 수식 뒤에서 본문 입력을 계속한다. 초안 입력은 Word 원본과 실행 취소 기록을 변경하지 않는다. Word가 변환하지 못하는 구조는 오류로 알리고 원본을 유지한다. 기존 Word 슬롯 직접 입력과 수식 표시 전환도 유지한다.

검증: Chromium 수식 22/22 통과. 인라인 5개, 다이얼로그 5개, 기존 Word 수식 12개를 함께 실행했다. 입력/Backspace 격리, 자동완성 ArrowDown/Enter, 취소, 한 번의 Undo, 수식 뒤 입력, 저장/재열기, 분수 구조 보존을 포함한다. Word 단위 시험은 599/600 통과 후 CSS 토큰 오류를 수정했고 해당 파일 2/2 재검증을 통과했다. Vite 빌드 통과. 기존 저장소 TypeScript 오류는 남아 있으며 이번 변경 파일의 진단은 해소했다. 로그: /tmp/word-inline-final.log, /tmp/word-inline-unit.log, /tmp/word-inline-chrome.log, /tmp/word-inline-build.log. 스크린샷: /tmp/word-math-inline.png.

## 2026-09-09 — W6b-3: 커서 기반 수식 도구 모음

수식 내부에 커서 또는 해당 수식 안의 선택 범위가 있으면 `수식 바로 편집` 도구를 표시한다. Word가 대상 수식을 결정하고 office-ui의 FloatingSurface, Button, Icon이 표면과 위치를 처리한다. 버튼은 대상과 커서를 유지한 채 기존 인라인 math-editor를 연다. 편집 중, 수식 밖 커서, 다른 입력창 포커스에서는 숨긴다. Esc로 닫은 도구는 같은 커서 상태에서 자동으로 다시 열리지 않는다. 수식을 다시 클릭하면 열린다. 적용 후 즉시 도구를 다시 띄우지 않는다.

새 시험에서 수식 뒤 문단 맨 앞의 커서가 Chromium의 getTargetRanges에서 앞 수식 끝으로 정규화되는 입력 결함을 발견했다. 공통 editor-view-dom은 단순 insertText의 접힌 범위에서 화면 커서와 모델 커서가 일치하고, 대상이 다른 부모의 이전 텍스트 끝으로 바뀐 경우에만 화면의 명시적 커서를 유지한다. 교체 범위와 같은 부모의 일반 서식 경계는 기존 동작을 유지한다. 인라인 수식 적용 후 포커스 복귀 시에도 모델 커서를 화면에 적용한다.
