# 편집 UI 공통화

점검일: 2026-09-14. 상태: 1단계의 속성 명령 처리와 Word·Slides 설정 창 적용 완료. 2단계에서 Note·Word의 표시·포커스·닫힘과 DOM 노드 위치 감지를 공유했다. 텍스트 범위 측정, Slides·Site 객체 도구, Site 설정 창별 적용 판단, 3단계는 남아 있다.

## 출발 기준

office-ui의 현재 데스크톱 기본 컴포넌트 정비를 1차 마감한다. 기존 컴포넌트를 유지하며 제품에서 발견한 결함은 계속 수정한다. 모바일, 날짜 범위·시간대, 서버 권한·공유 UI는 이번 마감 범위에 포함하지 않는다.

색상·간격·상태·모션은 office-ui에 둔다. office-editor-ui는 이 UI와 편집기의 선택·명령·구독을 연결한다. office-controls는 명령과 메뉴의 선언을 맡는다. 페이지 배치, 슬라이드 좌표, 표 병합, 수식 모델은 제품 또는 코어의 책임으로 유지한다.

## 이미 공유하는 코드

| 기능 | 현재 코드 | 확인한 적용 |
| --- | --- | --- |

| 선택 보존과 문맥 도구 | `context-toolbar.tsx`, `capture-text-selection.ts`, `use-selection-rect.ts` | Note 글자 도구·페이지 참조 |

새 패키지나 두 번째 버튼·팝업 체계는 만들지 않는다.

## 구현 순서

### 1. 속성 명령과 설정 창

2026-09-14 완료: usePropertyCommand가 편집기·문서 루트·선택 문맥별 실행 세션을 구분한다. 문맥 변경 후 아직 시작하지 않은 작업은 건너뛰고, 이전 실패·재시도를 새 문맥에 표시하거나 실행하지 않는다. A→B→A 이동도 새 세션이다. 새 대상의 대기 수를 따로 관리하되 실제 명령 큐는 직렬 순서를 유지한다. 같은 조작의 여러 명령은 버리지 않는다. 읽기 전용 거부, 실패 payload 재시도, 언마운트 후 대기 작업도 확인했다.

검증: 단위 검사 8개, Slides 3개·Site 2개 브라우저 검사, 공통 편집 UI 타입 검사(기존 미사용 항목 제외), Office 빌드 통과. 실제 통합 Slides에서 너비 10→11 적용 후 한 번의 실행 취소로 10 복원을 확인했다. 이미 시작한 명령의 트랜잭션을 강제로 취소하는 기능은 아니다. 이 훅은 시작 전 작업과 UI 피드백을 보호한다.

2026-09-14 설정 창 공통화: Word의 설정 훅을 `useEditorSettings`로 옮기고 Slides 크기 설정에 적용했다. 적용 결과를 기다린 뒤 닫으며, 처리 중 중복 적용·입력·닫기를 막는다. 거부·예외에는 초안을 유지하고 재시도한다. 변경 없는 적용은 명령을 실행하지 않는다. 편집기·문서·열림·대상 context가 바뀌면 새 세션으로 구분한다. 이전 작업의 완료 응답은 새 창에 영향을 주지 않는다. 제품이 명령과 선택 대상, 값 검증을 정한다.

검증: 공통 단위 검사 7개, Word 18개·Slides 2개 데스크톱 브라우저 검사, 편집 UI·Word·Slides 타입 검사(기존 미사용 항목 제외), Office 빌드 통과. 통합 Slides의 실제 크기 설정 창도 열어 확인했다. Slides 적용 실패 후 초안 유지·재시도·한 번의 실행 취소와 Word 기존 설정 동작을 확인했다.

2026-09-14 확대 적용: Slides 레이아웃·테마도 공통 훅을 사용한다. 레이아웃은 현재 슬라이드를 context로 구분한다. 같은 레이아웃을 다시 배치하는 동작에는 `skipUnchanged: false`를 사용해 실제 배치를 실행한다. 테마의 두 글꼴과 12색을 비교해 변경 없는 적용은 건너뛴다. 테마 창을 넓히고 이름 칸을 104px로 맞춰 긴 색상 이름의 잘림을 수정했다.

템플릿은 설정 명령이 아닌 문서 교체이므로 제품의 `useTemplateStart`에서 처리한다. 현재 문서 저장 완료를 기다리고, 중복 시작·선택 변경·닫기를 막는다. 실패 후 선택을 유지하며 재시도한다. 저장 중 편집기·문서·열림 세션이 바뀌면 이전 요청으로 문서를 교체하지 않는다. 공통 StatusNotice·StatusIndicator로 상태를 표시한다. 템플릿 교체를 한 번의 실행 취소가 가능한 설정으로 취급하지 않는다.

확대 적용 검증: 공통 설정·템플릿 단위 검사 13개, 데스크톱 브라우저 검사 23개가 범위별 통과했다. 편집 UI·Slides 타입 검사(기존 미사용 항목 제외)와 Office 빌드가 통과했다. 실제 통합 Slides의 테마 창을 확인했다. 기존 테마 검사의 중복 이름 선택자는 실제 선택 입력을 찾도록 수정했다.

남은 작업: Site 설정은 즉시 적용과 명시적 적용 흐름을 구분해 검토한다. 모든 제품의 모든 설정 창을 이전한 것은 아니다. Word·Slides의 이번 적용 묶음 이후 선택·포커스 점검으로 이동한다.

- 공통 `usePropertyCommand`의 대기 중 문서 교체·선택 변경·편집기 교체를 검증한다. 이전 대상의 실패나 재시도가 새 대상에 적용되지 않아야 한다.
- Word `use-formatting-dialog.ts`의 초안·적용·취소 계약과 Site·Slides 설정 창을 비교한다. 두 번째 제품에서 같은 요구를 확인한 뒤 공통 훅으로 옮긴다.
- 읽기 전용, 변경 없음, 명령 거부, 예외, 재시도, 적용 중 닫기를 같은 규칙으로 처리한다.
- 명령 payload와 선택 대상의 해석은 제품에 남긴다. 모든 명령을 하나의 범용 폼으로 바꾸지 않는다.

완료 기준: 실제 두 제품에서 입력 초안 유지, 한 번의 실행 취소, 실패 후 재시도, 문서 교체 후 이전 작업 차단을 확인한다.

### 2. 선택 도구의 표시와 포커스

2026-09-14 첫 적용: `useEditorContextVisibility`를 Note의 공통 ContextToolbar와 Word 수식 도구에 연결했다. 편집기·도구 내부의 포커스만 허용하고, 별도 수식 입력·외부 필드·창 포커스 상실·읽기 전용에서는 숨긴다. Escape 닫힘은 일시적인 대상 위치 상실이나 포커스 이동으로 초기화하지 않는다. 다른 대상과 제품의 명시적 재선택은 다시 열 수 있다. Word는 KaTeX 표시의 입력 소유 마커를 실제 편집 입력과 구분한다. Note는 창 포커스 복귀 시 선택 위치를 다시 측정한다.

검증: 공통 단위 검사 11개, Note 12개·Word 12개 데스크톱 브라우저 검사가 범위별 통과했다. Word 검사의 상세 도구 진입 경로를 현재 UI에 맞췄고, 툴바 검사는 자동완성 선택과 수식 확정을 혼동하지 않도록 숫자로 입력했다. 공통 편집 UI·Word 타입 검사(기존 미사용 항목 제외), Office 빌드 통과. 실제 통합 Word에 검증용 `x+2` 수식을 넣어 재선택과 내부 편집 중 숨김을 확인했다.

2026-09-14 DOM 노드 위치: office-ui에 `visibleElementRect`·`observeElementAnchor`를 추가했다. 창·visual viewport와 overflow 조상의 표시 영역을 검사한다. 스크롤, 크기 변경, 조상 class/style 변경, 대상 DOM 교체를 감지하고 같은 프레임의 갱신을 합친다. office-editor-ui `useNodeAnchor`가 현재 문서의 노드와 연결하며 기존 `useNodeRect`는 좌표만 반환한다. Note 표·블록·코드 도구와 Word 수식 도구에 적용했다. 일부가 보이면 원래 좌표를 유지하고 완전히 가려지면 숨긴다. Word의 별도 노드 측정 코드를 제거했다.

실제 Note에서 표 버튼의 아이콘·글자 겹침도 확인했다. 아이콘 전용 버튼을 공통 Button·Tip 조합으로 바꿨다. 검증: DOM 경계·감지·정리 단위 검사 4개, Word 8개·Note 11개 데스크톱 브라우저 검사가 범위별 통과했다. office-ui·office-editor-ui·Word·Note 타입 검사(기존 미사용 항목 제외), Office 빌드 통과. 실제 통합 Note에 ‘선택 도구 경계 확인’ 문서와 표를 만들고 도구 배치를 확인했다.

남은 작업: 텍스트 Range 측정의 화면 경계와 Slides·Site 객체 도구 적용을 검토한다. 캔버스 좌표 계산·회전·clip-path·CSS 애니메이션의 모든 중간 프레임을 통합한 것은 아니다.

- Note의 공통 문맥 도구와 Word `math-context-toolbar.tsx`의 구독·위치 측정·닫힘 상태를 비교한다.
- 공통으로 묶을 대상은 표시 조건, 소유 편집기, 포커스 보존, 스크롤·확대 후 위치 갱신이다.
- 수식·이미지·표의 대상 판정, 드래그 계산, 페이지·캔버스 좌표 변환은 제품 어댑터에 둔다.
- 수식 입력 중 부모 편집기의 메뉴와 단축키가 실행되지 않아야 한다. Escape로 닫은 도구는 같은 선택에서 즉시 다시 열리지 않아야 한다.

완료 기준: 문단 선택, 객체 선택, 내부 수식 편집, 다른 편집기로 포커스 이동, 확대·스크롤을 데스크톱에서 검증한다.

### 3. 메뉴·툴바 명령 실행

- `Controls`와 `ControlRows`를 우선 사용한다. 제품별 `onRun`에 남은 중복 선택 복원과 실패 처리를 점검한다.
- 비활성·혼합 값·실행 중·실패 상태를 공통 컴포넌트로 표시한다.
- 제품 메뉴 항목과 도구 구성은 각 제품에 둔다.

완료 기준: 버튼, 메뉴, 명령 검색에서 같은 동작을 실행해도 선택 대상과 실행 취소 결과가 같아야 한다.

## 검증 방식

각 묶음은 공통 API 변경, 제품 적용, 필요한 회귀 검사, 열린 제품 브라우저 확인, 로드맵 갱신까지 완료한다. 새 훅을 export한 것만으로 완료 처리하지 않는다. 모바일 화면 검사는 진행하지 않는다.
