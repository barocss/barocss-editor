# Wonffice 인터페이스 기준

기준안 01 · 2026-09-14

이 문서는 `office-ui`의 시각 규칙과 사용 기준을 정의한다. 현재 구현의 기준선이며, 모든 제품의 모든 화면을 검증했다는 뜻은 아니다.

## 확인할 화면

- 통합 개발 서버: `/design-system/index.html`
- 전체 컴포넌트 목록: `/design-system/index.html?catalogue`
- 소스: `apps/gallery/src/design-system.tsx`, `apps/gallery/src/gallery.tsx`
- 구현 값: `src/tokens.css`

기준표는 현재 CSS 변수 값을 읽는다. 예시는 제품의 실제 공통 컴포넌트를 사용한다. 로컬 상태로 동작하며, 사용자 문서를 읽거나 저장하지 않는다. 테마는 문서 루트에 적용해 포털 메뉴와 다이얼로그에도 전달한다.

## 패키지 책임

| 패키지 | 책임 |
| --- | --- |
| office-ui | 기본 컴포넌트, 시각 토큰, 포커스, 메뉴 열기·닫기, 입력 처리 |
| office-icons | 아이콘 형태, 선 두께와 기본 크기 |

제품 CSS는 배치와 제품 렌더링을 담당한다. 공통 버튼의 높이·테두리·상태 색을 제품별로 다시 정의하지 않는다. 새 요구가 있으면 먼저 공통 컴포넌트의 명시적인 속성이나 시각 토큰으로 표현할 수 있는지 확인한다. 문서 본문 스타일은 UI 토큰과 분리한다.

## 객체 선택 도구 — 규격 보완 대상

2026-09-14 기본 표시 적용: `office-selection-frame`과 `office-selection-handle`을 Word·Slides에 연결했다. Site 선택 프레임은 같은 클래스를, 모서리는 같은 토큰을 사용한다. CSS 표시 계약이므로 기존 DOM 구조와 포인터 명령을 유지한다. 새 React 오버레이나 편집기 구독 계층을 중복으로 만들지 않는다.

| 토큰 | 값 | 의미 |
| --- | --- | --- |
| `--ou-selection-line` | 1px | 화면상의 선택선 |
| `--ou-selection-handle-size` | 8px | 보이는 핸들 |
| `--ou-selection-hit-size` | 16px | Word·Slides의 포인터 영역 |
| `--ou-selection-radius` | 1px | 모서리 핸들 둥글기 |
| `--ou-selection-rotate-gap` | 32px | Slides 회전 핸들의 중심과 객체 위쪽 경계 간격 |
| `--ou-selection-ink` / `--ou-selection-fill` | accent / panel | 테마를 따르는 선과 채움 |

확대된 부모 안에서는 `--ou-selection-scale`에 실제 부모 배율을 전달한다. 화면 좌표를 이미 계산한 Word·Slides는 기본값 1을 사용한다. Site는 `--st-zoom`을 연결한다. 프레임의 `::after`는 역배율 표시를 담당한다. 핸들의 `::before`는 입력 영역, `::after`는 표시 영역이다. 제품은 이 가상 요소에 다른 장식을 추가하지 않는다.

갤러리 `/design-system/index.html#selection-tools`에서 상태와 배율을 비교한다. 이는 표시 예시이며 잠금·편집 상태를 모든 제품에 새로 연결했다는 뜻은 아니다. 브라우저 8개 검사가 범위별 통과했다. Word의 취소·비율 유지·저장/재열기, Slides의 크기 변경·회전·undo, Site의 모서리 크기 변경을 확인했다. 표 전용 핸들·가이드·크기 표시 및 제품 경계 잘림 검증은 후속 범위다.

객체 선택 동작은 Word·Slides·Site의 오버레이에 남아 있다. 다음 규칙 중 가이드와 전체 상태 연결은 구현 방향이며 적용 완료를 뜻하지 않는다.

- office-ui는 선택선·핸들·회전 연결선·가이드·크기 표시의 시각 토큰과 표시 부품을 담당한다. DOM과 SVG 사용처가 같은 토큰을 사용할 수 있게 한다.
- office-editor-ui는 편집 선택 구독, 표시할 상태, 문맥 도구의 표시 시점과 입력 소유권을 연결한다.
- 제품은 페이지·캔버스·문서 흐름의 좌표 변환과 실제 조작 명령을 담당한다. 공통 크기 계산은 기존 office-canvas를 재사용한다. 모든 좌표계를 하나의 오버레이에 강제로 합치지 않는다.
- hover·단일 선택·다중 선택·텍스트 편집·크기 조절·회전·잠금·읽기 전용 상태를 구분한다. 지원하지 않는 조작의 핸들은 표시하지 않는다.
- 확대율이 바뀌어도 선택선과 핸들의 화면상 두께·크기는 일정하게 유지한다. 표시 크기와 포인터 입력 영역은 따로 정의한다.
- 의도한 뷰포트 밖은 가리되, 객체 부모의 overflow 때문에 핸들이 잘리지 않게 한다. 메뉴는 선택 프레임과 별도 레이어 정책으로 배치한다.
- 핸들 드래그가 텍스트나 테이블 셀 선택을 시작하지 않게 한다. Escape는 진행 중 조작을 취소하며 확정 조작은 실행 취소 한 번으로 복원한다.

먼저 갤러리에 상태·확대율·경계 비교 예시를 추가한다. Word 이미지·Slides 도형·Site 블록에서 실제 조작을 검증한 뒤 적용 범위를 넓힌다. Note 표의 행·열 핸들과 인라인 객체는 해당 문서 흐름에 맞춰 별도 검증한다.

## 표 경계·가이드·크기 표시 — 2026-09-14

- `SelectionReadout`은 뷰포트 좌표 `at: { x, y }`와 제품이 만든 표시 문자열을 받는다. body 포털에 표시하며 가장자리에서 위치를 바꾼다. 포커스·포인터·Escape·문서 선택을 소유하지 않는다. 제품은 드래그가 끝나거나 취소되면 제거한다. 숫자가 계속 바뀌므로 실시간 음성 알림은 끈다.
- Note 표 드래그, Slides 드래그, Site 실시간 크기 표시에 적용했다. 좌표 측정과 단위 변환은 제품에 남긴다.
- DOM으로 구현한 Word 표 경계 도구는 같은 `office-selection-readout` 표시 계약과 토큰을 사용한다. React 의존성을 추가하지 않는다. 소수 픽셀까지 측정해 화면 경계를 넘지 않게 배치한다.
- `--ou-selection-readout-bg`·`--ou-selection-readout-ink`는 panel·ink를 따른다. 숫자는 12px, tabular-nums를 사용한다. 값과 단위는 제품이 정한다.
- `--ou-selection-guide`는 정렬 스냅을 나타내는 분홍색이다. 사용자가 배치한 안내선과 표 크기 조절 경계는 이 색으로 합치지 않는다.
- Note 표 경계의 `--ou-table-boundary-hit`는 8px, `--ou-table-boundary-line`은 2px이다. 입력 영역을 보이는 선보다 넓게 유지한다. Word 경계의 탐지 방식은 기존 포인터 계산을 유지한다.
- 표 행 추가·열 너비 변경은 제품 명령을 사용한다. 드래그 중 셀 선택을 시작하지 않는다. Escape 취소와 한 번의 undo를 검증한다.

검증: 브라우저 11개, 공통 UI·갤러리 타입 검사와 Office 빌드 통과. Word 표의 오른쪽 화면 경계, 공통 표시의 390px·1440px 화면 및 포커스·Escape 전달을 확인했다. 고정 표시와 작은 객체의 후속 적용은 다음 절을 따른다.

## 작은 객체·고정 크기 표시 — 2026-09-14

- `selectionResizeHandles(width, height, active?)`는 화면상 크기를 받는다. 16px 포인터 영역이 겹치지 않는 크기 조절 핸들을 반환한다. 활성 핸들, 오른쪽 아래, 나머지 모서리, 변 가운데 순으로 우선한다. 드래그 중 활성 핸들이 사라지지 않게 한다.
- Word 이미지·Slides 객체에 적용했다. 12px 정사각형은 오른쪽 아래 핸들 하나를 표시한다. 화면상 32px 정사각형은 여덟 핸들을 표시한다. 모델 크기와 크기 변경 명령은 유지한다. 회전 핸들과 연결 시작점은 이 함수의 범위 밖이다.
- 고정 크기 표시는 `SelectionReadout`의 선택적 `getAnchor`로 실제 객체 사각형을 제공한다. React 렌더 없이 바뀌는 배율·이동도 프레임마다 추적한다. 제품은 객체가 캔버스 밖에 있으면 null을 반환한다. 포털 표시는 숨겨지며, 객체가 돌아오면 다시 나타난다.
- Site의 고정 크기 표시에 적용했다. 표시 숫자는 모델 크기를 유지하고, 글자 크기는 확대율에 따라 커지지 않는다.
- 갤러리에서 작은 객체와 50/100/200% 배율을 비교한다. 단위 5개, 브라우저 14개가 통과했다. Site 캔버스 밖 이동·복귀도 추가 확인했다. Word·Slides는 작은 객체의 실제 크기 변경과 한 번의 undo를 확인했다. 공통 UI·갤러리·Slides 타입 검사와 Office 빌드가 통과했다. Slides 타입 검사는 기존 미사용 항목 검사를 제외했다.

## 공통 모션 — 2026-09-14

| 표면 | 열기 토큰 | 닫기 |
| --- | --- | --- |
| 선택 목록·Menu·FloatingSurface | `--ou-motion-popup`: 140ms, 페이드 + 3px | 즉시 제거 |
| 색상 팝오버 | 같은 popup 토큰, 페이드만 사용 | 즉시 제거 |
| Tooltip | `--ou-motion-tooltip`: 100ms 페이드 | 즉시 제거 |
| Dialog | `--ou-motion-dialog`: 180ms 페이드 | `--ou-motion-exit`: 100ms 페이드 |
| Drawer·SidePeek | `--ou-motion-drawer`: 200ms, 20px 측면 이동 | `--ou-motion-drawer-exit`: 140ms, 12px 측면 이동 |

모션은 office-ui의 표시 계약이다. 제품별 진입 효과를 추가하지 않는다. 기존 `--ou-motion-enter`는 호환용으로 유지한다. Tooltip의 instant-open 상태는 즉시 표시한다. 색상 패널은 화면 높이를 채울 수 있으므로 이동하지 않는다. 배치 준비 후 시작하고, 좌표 변경만으로 다시 시작하지 않는다. 선택선·핸들·가이드·크기 표시는 위치 전환을 사용하지 않는다.

키보드 처리와 포커스 이동은 애니메이션 종료를 기다리지 않는다. 닫는 Dialog·Drawer는 포인터 입력을 받지 않으며, 기존 Radix 종료·포커스 복귀 수명 주기를 유지한다. `prefers-reduced-motion: reduce`에서는 진입·종료 애니메이션을 끈다. `/design-system/index.html#motion`에서 실제 선택 목록·툴팁·메뉴·팝오버·Dialog·Drawer·색상 패널을 비교한다.

## 검색형 선택과 태그 — 2026-09-14

`SearchSelect`는 옵션의 안정적인 `id`, `label`, 선택적 `description`·`disabled`를 받는다. 단일 선택은 문자열 `value`와 `onChange(string)`, 다중 선택은 `multiple`과 문자열 배열 `value`·`onChange(string[])`를 사용한다. 데이터 검색 API와 저장 처리는 포함하지 않는다. 현재 전달된 옵션 목록의 이름·설명을 검색한다.

```tsx
<SearchSelect ariaLabel="원본 자료" options={documents} value={sourceId} onChange={setSourceId} />
<SearchSelect multiple ariaLabel="태그" options={tags} value={tagIds} onChange={saveTags} />
```

- 단일 선택은 확정 후 닫는다. 다중 선택은 열어 둔다. 선택 개수·개별 제거·전체 해제를 제공한다.
- 검색 입력이 키보드 포커스를 소유한다. 방향키는 선택 불가 항목을 건너뛰고 Enter는 활성 항목을 선택한다. 한글 조합 중에는 선택하지 않는다. 검색어가 없는 결과는 상태 문구로 표시한다.
- Dialog 안에서는 중첩 포커스 범위를 사용한다. Escape는 목록부터 닫고 트리거로 복귀한다. 외부 입력을 클릭한 경우 해당 입력의 포커스를 유지한다.
- 긴 항목명은 줄바꿈한다. 설명은 작은 보조 글씨로 분리한다. `readOnly`·`disabled`에서는 값 변경과 태그 제거를 제공하지 않는다.
- `SelectionTag`는 항목 열기와 제거를 별도 버튼으로 제공한다. 제거 시 폼 label의 기본 동작이 다른 컨트롤을 활성화하지 않게 한다. 찾을 수 없는 항목은 점선으로 표시할 수 있다.
- Note 관계 선택은 기존 저장 큐·실패 복구를 유지한다. Office 원본 참조 선택과 Site choices에도 연결했다. Site는 기존 줄바꿈 구분 저장 형식을 유지하며, 다중 선택 필드 옵션을 보존한다.
- 갤러리 `#search-select`에서 단일·다중·읽기 전용·저장 거부 예시를 비교한다. 실제 제품의 관계 계산·참조 연결·태그 재열기와 함께 확인한다. 원격 검색·가상 목록·비동기 로딩 상태는 이번 범위에 포함하지 않는다.

## 파일·미디어 선택 — 2026-09-14

- `FilePick`은 기존 파일 선택 버튼으로 유지한다. 드래그가 필요한 화면은 별도의 `FileDropZone`을 사용한다.
- `FileDropZone`은 파일 하나만 받는다. `accept`·`maxBytes`·빈 파일 검사를 선택과 드롭에 동일하게 적용한다. 여러 파일을 놓으면 첫 파일만 처리하지 않고 오류를 표시한다.
- `onPick(file)`이 반환한 Promise가 끝날 때까지 처리 중 상태를 표시하고 재입력을 막는다. 실패하면 오류를 표시하고 같은 파일을 다시 선택할 수 있다. 실제 진행률이나 취소 기능은 임의로 만들지 않는다.
- 형식 검사는 입력 안내다. 이미지 해석, 저장, 삽입 명령은 제품이 수행한다. Word는 기존 PNG/JPEG/WebP/GIF 5MB 제한과 이미지 해석 검사를 유지한다. 저장한 커서 위치로 삽입한다.
- `FileItem`은 파일 이름·크기와 선택적 제거 버튼을 표시한다. 서버 업로드 완료를 뜻하지 않는다.
- `MediaSelect`는 문서 자산의 `id`·`label`·`src`·선택적 `description`을 받아 미리보기와 검색 목록을 표시한다. `없음`은 빈 ID를 전달한다. 미리보기 실패는 대체 문구로 표시하며 원본 참조를 지우지 않는다.
- Site 이미지 데이터 필드는 기존 `asset:` 참조를 저장한다. 미리보기 주소는 제품의 `assetSrc`로 해석한다. 파일 복사나 서버 업로드를 하지 않는다.

```tsx
<FileDropZone label="그림 파일" accept="image/png,image/jpeg" maxBytes={5 * 1024 * 1024}
  hint="PNG, JPEG · 최대 5MB" onPick={decodeImage} />
<MediaSelect ariaLabel="문서 이미지" options={assets} value={assetId} onChange={setAssetId} />
```

갤러리 `#files`에서 선택·드롭·처리 실패·비활성·미리보기 실패를 비교한다. 범위는 로컬 파일 하나와 기존 문서 이미지 선택이다. 다중 업로드·진행률·서버 자산 관리는 후속 범위다.

## 명령 검색 — 2026-09-14

- `CommandSearch`는 `commands`·`recentIds`·`onPick(id)`를 받는다. 편집기 명령을 직접 실행하지 않는다.
- 명령은 고유 `id`, `label`, `category`와 선택적 `keywords`, `hint`, `disabled`, `disabledReason`을 가진다. 제품이 현재 문서 상태를 기준으로 활성 여부를 전달한다.
- 방향키는 실행 가능한 항목 사이를 이동한다. Enter는 현재 항목을 실행한다. 한글 조합 중 Enter는 실행하지 않는다. Escape는 실행 없이 닫고 포커스를 복원한다.
- 실행 불가 항목은 검색 결과에 남기고 분류와 이유를 표시한다. 결과가 없으면 별도 안내를 표시한다. 검색어가 없을 때 최근 명령을 먼저 표시한다.
- `onPick`은 검색 Dialog가 닫히고 포커스를 복원한 뒤 호출한다. 다른 편집 Dialog를 열 때 포커스가 이전 검색 버튼으로 돌아가지 않게 한다. 공통 `Dialog.onClosed`가 이 시점을 제공한다.
- Word는 검색 전 선택과 문서 ID를 보관한다. 실행 전에 같은 문서인지 확인하고 선택을 복원한다. 검색 입력은 본문을 변경하지 않는다. 실제 실행과 오류 처리는 Word가 담당한다.
- Word 메뉴와 기본 서식 18개, Slides 메뉴와 직접 실행하는 툴바 명령을 연결했다. Slides는 현재 슬라이드와 선택도 보관하며, 검색 중 문서나 현재 슬라이드가 바뀌면 실행을 막는다.
- Slides의 파일 선택, 색·글꼴 등 값 입력 도구는 검색에서 제외했다. 최근 5개는 현재 세션에서만 보관한다. Note 연결은 후속 범위다.
- Site는 관리·페이지 편집 화면의 기존 메뉴를 검색한다. 글 고치기 모드의 실행 제한을 유지한다. 검색 전 문서·편집 대상·페이지·선택을 보관하고, 편집 화면이 바뀌면 실행을 막는다. 속성 값 입력 도구는 검색에 포함하지 않는다.
- `CommandSearchTrigger`는 편집기 선택을 유지하는 공통 검색 버튼이다. 작은 화면에서는 이름을 숨기고 검색 아이콘을 표시한다. 접근 가능한 이름은 유지한다.

```tsx
<CommandSearch open={searchOpen} onOpenChange={setSearchOpen}
  commands={commands} recentIds={recentIds} onPick={runSavedSelectionCommand} />
```

갤러리 `#commands`에서 실행 불가·결과 없음·최근 명령·후속 Dialog를 확인한다. Word·Slides·Site 헤더의 `명령 검색`은 실제 문서 명령을 실행한다.

## 작업 상태 — 2026-09-14

- `TaskStatus`는 `title`, `phase`, `description`, 선택적 `progress`, `actions`, `onDismiss`를 받는다. 상태는 `running`·`success`·`error`·`cancelled`다. 작업 실행과 저장은 제품이 담당한다.
- `progress`는 제품에서 측정한 0–100 값이다. 값이 없거나 유효하지 않으면 진행 막대를 표시하지 않는다. 시간 경과로 임의 진행률을 만들지 않는다.
- 처리 중에는 자동 닫기와 닫기 버튼을 제공하지 않는다. 취소가 가능한 작업만 `actions`로 취소 버튼을 전달한다. 닫기는 취소를 뜻하지 않는다.
- 완료와 실패는 사용자가 닫거나 새 작업을 시작할 때까지 유지한다. 실패는 이유와 가능한 다음 작업을 표시한다. 오류 안내 자체가 편집기 포커스를 가져가지 않는다.
- `TaskStatusRegion`은 화면 우측 하단의 공통 배치다. `label`과 `children`을 받는다. 여러 작업이 같은 영역에 쌓이며, 마지막 작업을 닫으면 영역을 제거한다. 390px 화면에서도 양쪽 16px 여백을 유지한다. Dialog보다 낮은 레이어를 사용한다. `TaskStatus` 자체는 일반 문서 흐름에도 배치할 수 있다.
- Word·Slides·Site의 JSON `FileActions`는 읽기·변환·출력 오류와 중복 실행을 처리한다. 파일 읽기 도중 문서가 바뀌면 결과를 적용하지 않는다. 실패한 출력은 재시도, 실패한 읽기는 다른 파일 선택을 제공한다.
- Slides는 덱 형식과 파일 이름 정의만 전달한다. `confirmReplace`에서 변경 확인을 수행하고, 확인한 경우에만 `beforeReplace` 저장 훅을 실행한다. 확인의 `false`는 취소, 저장 훅의 `false`는 실패다. Word·Site의 기존 확인·저장 정책은 유지한다.
- 다운로드 링크 실행은 “다운로드 요청됨”으로 표시한다. 브라우저의 디스크 저장 완료를 확인했다고 표시하지 않는다. 기존 자동 저장 상태와 별개다.
- 파일 읽기·준비 작업에는 아직 실제 수치 진행률이나 중간 취소가 없으므로 해당 UI를 표시하지 않는다. 문서 교체 확인에서 사용자가 거부하면 취소 상태를 표시한다.

```tsx
<TaskStatus title="파일 준비 중" phase="running" description={fileName} />
<TaskStatus title="파일 처리 실패" phase="error" description={errorMessage}
  actions={<Button onClick={retry}>다시 시도</Button>} onDismiss={dismiss} />
```

갤러리 `#tasks`는 예시 상태를 수동으로 전환한다. 실제 파일을 읽거나 저장하지 않는다. 작업 실행 큐는 제공하지 않는다. `TaskStatusRegion`은 표시 영역만 공유한다.

### DOCX·HTML 출력 적용

- Word DOCX는 변환 안내 Dialog 안에서 준비 상태와 오류를 표시한다. 파일 준비 후 기존 변환 주의사항을 유지한다. 변환 실패는 현재 문서를 다시 변환하고, 다운로드 실패는 준비한 파일로 다시 다운로드한다.
- 성공 안내는 상위 문서 작업 Dialog에 남는다. 다운로드 요청을 실제 디스크 저장 완료로 표시하지 않는다. DOCX 취소는 문서를 변경하지 않는다.
- Site 페이지 HTML과 사이트 ZIP은 마지막 본문 입력 반영 후 출력한다. 출력 중에는 추가 출력 요청을 받지 않는다. 실패 후 재시도는 같은 문서·페이지 대상을 사용하며, 문서가 바뀌면 이전 요청의 재시도를 중단한다.
- Site 파일 작업과 HTML/ZIP 출력은 서로 다른 카드로 같은 영역에 표시한다. 한 카드를 닫아도 다른 카드가 남는다.
- 상태를 그린 뒤 동기 변환을 실행한다. 변환을 작업 스레드로 분리한 것은 아니다. 실제 진행률과 중간 취소는 제공하지 않는다.

## 컴포넌트 선택

| 사용 목적 | 컴포넌트 | 기준 |
| --- | --- | --- |
| 작업 실행 | Button, IconButton | 화면에서 주요 작업만 강조한다. 아이콘에는 동작 이름을 제공한다. |
| 켜기·끄기·혼합 값 | ToolbarToggle, PropertyToggle | 문서 상태를 전달한다. 혼합 값은 꺼짐과 다르게 표시한다. |
| 하나의 값 선택 | ChoiceSelect, PropertyChoice | 선택된 값을 표시한다. 빈 값과 비활성을 구분한다. |
| 텍스트 편집 | TextField | 검색은 onChange, 문서 속성은 onCommit을 기본으로 한다. |
| 숫자 편집 | NumberField, PropertyNumber | 단위와 범위를 지정한다. Enter는 적용, Escape는 입력 취소이다. |
| 추가 명령 | MenuBar, Menu | 키보드 탐색과 Escape 닫기를 공유한다. 잘리지 않도록 포털로 표시한다. |
| 제품 메뉴 | ProductMenu | 제품 이름과 화살표를 함께 표시한다. 호스트가 문서 작업을 연결한다. |
| 기본 도구 | RibbonToolbar compact | 한 줄을 기본으로 한다. 큰 리본은 필요할 때 펼친다. |
| 속성 편집 | PropertyPanel, PropertyGroup, PropertyRow | 같은 종류의 값은 같은 순서와 폭으로 배치한다. |

TextField 검증은 호출자가 담당한다. `invalid`는 오류 테두리와 `aria-invalid`를 설정한다. `describedBy`에는 실제 설명 요소의 ID를 전달한다. 빈 값, 혼합 값, 읽기 전용은 오류로 처리하지 않는다.

```tsx
const invalid = !name.trim();
<>
  <TextField ariaLabel="문서 이름" value={name} onChange={setName}
    invalid={invalid} describedBy={invalid ? 'name-error' : undefined} />
  {invalid && <p id="name-error">이름을 입력하세요.</p>}
</>
```

## 입력칸과 메뉴 상태 — 2026-09-14

- `PropertyToggle`: 표시 상자는 16px, 입력 대상은 24px이다. 체크 표시는 `office-icons`를 사용한다. 선택·hover·키보드 포커스·비활성을 구분한다. `--ou-accent-ink`로 테마별 체크 대비를 유지한다.
- 속성 입력칸은 `office-field`를 통해서만 배경과 테두리를 받는다. 패널의 모든 `input`에 배경을 지정하지 않는다. 이 규칙은 체크박스 선택 배경이 덮이는 문제를 방지한다.
- 속성 입력칸은 옅은 배경을 사용한다. hover에는 구분선, focus에는 강조선을 표시한다. 오류선은 focus에서도 유지한다. Enter 적용과 Escape 취소는 유지한다.
- `ChoiceSelect`와 `Menu`의 항목 높이는 최소 30px이다. 체크 표시의 16px 공간은 선택 여부와 무관하게 유지한다. 선택 메뉴의 현재 값은 체크와 강조 배경으로 표시한다.
- 제품은 공통 컴포넌트를 가져오면 이 규칙을 받는다. 제품별로 체크박스나 메뉴 스타일을 복제하지 않는다.

검증: 갤러리 5개와 실제 네 제품 비교 1개 브라우저 검사. 실제 Slides 객체의 표시·잠금 체크와 속성 패널도 확인한다. 작은 화면에서 선택 도구가 많을 때의 스크롤·메뉴 접근, 복잡한 색상 편집은 후속 검토 범위이다.

## 버튼 기준 — 2026-09-14

버튼 상세 화면: `/design-system/index.html#buttons`.

| 역할 | 기준 |
| --- | --- |
| 기본 Button | 작업 표면 배경과 얇은 구분선 |
| 강조 Button | 강조 배경과 `--ou-accent-ink` 글자색. 한 영역의 주요 동작에만 사용 |
| 보조 Button | 투명 배경. hover와 누름 상태에서 배경 표시 |
| 선택 버튼 | 옅은 강조 배경과 강조색 텍스트. hover/active에서도 선택 유지 |
| 혼합 버튼 | 선택 배경과 빗금. `aria-pressed="mixed"` 유지 |
| 아이콘 버튼 | 16px 아이콘. 작은 버튼은 24px 영역 안에 14px 아이콘 |
| 다이얼로그 버튼 | 32px 높이. 기본 버튼과 같은 색상·상태 규칙 |

`Button`, `IconButton`, `ToolbarToggle`, 다이얼로그 닫기 버튼은 `office-button` 상태 규칙을 공유한다. 입력칸의 `office-field`를 사용하지 않는다. 기존 CONTROL에 입력칸 표식을 넣으면 강조 버튼의 글자색과 속성 패널 버튼의 배경이 덮일 수 있다. 입력칸에는 FIELD_CONTROL을 사용한다. ChoiceSelect의 버튼은 값 선택을 위한 입력칸이므로 이 분류에 포함된다.

Button과 DialogButton은 기본 버튼 속성과 이벤트를 전달한다. 기본 type은 button이며, 폼 제출은 type="submit"으로 지정한다. form, name, value도 보존한다. disabled 버튼은 실행하지 않는다. 키보드 포커스는 사방의 테두리로 표시하며, 상태 전환 때 버튼 위치와 크기는 변하지 않는다.

버튼 3개, 기존 갤러리 5개, 실제 네 제품 비교 1개 브라우저 검사 통과. 일반 표면·속성 패널·다이얼로그의 강조색, 양쪽 테마, hover/active, Enter/Space, 비활성, 아이콘 정렬, 폼 제출을 검증했다. 개별 컴포넌트 전체 점검은 계속 진행한다. 다음 대상은 선택 상자와 숫자·텍스트 입력칸이다.

## 다이얼로그·Drawer 기준 — 2026-09-14

상세 화면: `/design-system/index.html#modals`.

- 제목과 하단 동작 영역은 유지하고 본문만 스크롤한다. 제목·설명은 긴 내용을 줄바꿈한다.
- 공통 본문 여백은 20px이다. 작은 화면에서는 16px로 줄인다. Drawer는 화면 높이를 사용하며, 600px 이하에서는 화면 너비를 채운다.
- Dialog를 화면 중앙에 놓을 때 transform을 사용하지 않는다. 내부의 fixed 색상 팝업은 화면 좌표를 유지해야 한다.
- 색상·선택 팝업에서 Escape를 누르면 가장 위의 팝업만 닫는다. 다음 Escape로 부모 창을 닫는다. 이미 처리한 Escape 이벤트를 다시 처리하지 않는다.
- 창을 닫으면 실행 전의 연결된 요소로 포커스를 돌려준다. 조합 중 Escape는 창을 닫지 않는다.
- 공통 Dialog와 Drawer가 같은 제목·본문·하단 CSS 역할을 사용한다. 제품에서 별도 버튼과 창 스타일을 복제하지 않는다.

검증: 새 브라우저 5개와 색상·메뉴 5개, 실제 네 제품 비교 1개가 최종 통과했다. 기존 버튼 3개·갤러리 5개도 통과했다. 실제 Slides의 테마 색 편집과 취소, 390×460 화면, 밝은·어두운 테마를 확인했다. office-ui·갤러리 타입 검사와 Office 빌드도 통과했다. 조합 검사는 합성 키 이벤트이며 실제 OS 입력기 검증은 아니다. SidePeek의 전체 제품 흐름과 모든 중첩 창 조합은 이번 검증 범위에 포함하지 않는다. 다음은 로딩·저장 실패·복구 상태다.

## 로딩·저장·복구 기준 — 2026-09-14

상세 화면: `/design-system/index.html#feedback`.

- `StatusIndicator`는 짧은 진행 상태를 표시한다. 저장 완료는 조용한 아이콘과 글자를 사용한다. 실패는 오류색과 아이콘, 충돌은 안내 아이콘과 글자로 구분한다. 색만으로 의미를 전달하지 않는다.
- `busy`는 진행 아이콘을 표시한다. 동작 줄이기로 설정한 환경에서는 회전하지 않는다. 진행 표시는 입력 포커스를 이동하지 않는다.
- `StatusNotice`는 제목, 설명, 실행 버튼을 배치한다. 화면이 좁으면 버튼을 다음 줄로 보낸다. 사방에 같은 두께의 경계선을 사용한다. 자동으로 사라지지 않는다.
- 저장 로직과 재시도는 제품이 소유한다. UI가 임의로 저장 성공을 표시하지 않는다. `office-editor-ui/DocumentSaveStatus`가 공통 문서 세션의 결과를 표시 상태로 연결한다.
- 실패한 저장은 현재 입력을 유지한 채 다시 시도한다. 공통 보관함은 처리 중 같은 동작을 중복 실행하지 않는다. 충돌한 초안은 최신 원본과 분리하여 새 자료로 복구한다.
- 갤러리는 실제 저장을 하지 않는다고 표시한다. 실제 제품의 저장 검증과 갤러리 시뮬레이션을 구분한다.

```tsx
<StatusIndicator busy={saving} tone={failed ? 'danger' : 'neutral'}>
  {saving ? '저장 중' : failed ? '저장 실패' : '저장됨'}
</StatusIndicator>
<StatusNotice tone="danger" title="변경 사항을 저장하지 못했습니다"
  actions={<Button disabled={saving} onClick={retry}>저장 다시 시도</Button>}>
  이 창을 유지하고 다시 시도하거나 파일로 내보내세요.
</StatusNotice>
```

검증: 상태 검사 4개, 실제 네 제품 비교 1개, 기존 모달 5개가 범위별 통과했다. Word는 쓰기 실패와 반복 재시도 후 입력 보존·재열기를 검증했다. Slides는 두 창 충돌 후 새 자료 복구와 최신 원본 보존을 검증했다. 390px 화면, 두 테마, 동작 줄이기를 확인했다. office-ui·갤러리 타입 검사와 Office 빌드 통과. office-editor-ui·Word의 기본 타입 검사는 의존 패키지의 미사용 항목 오류가 남아 있다. office-editor-ui는 미사용 항목 검사만 제외한 타입 검사에서 통과했다. 서버 저장·오프라인 동기화와 모든 제품의 실패 경로 전체 검증을 의미하지 않는다.

## 탭·목록·빈 상태 기준 — 2026-09-14

상세 화면: `/design-system/index.html#navigation`.

- `PropertyTabs`는 `RibbonTabs`의 패널 형태를 사용한다. 방향키·Home·End는 활성 탭을 바꾸며 비활성 탭을 건너뛴다. Tab 키의 진입점은 하나다. 패널 탭 클릭은 해당 탭에 포커스를 둔다. 리본 탭은 기존 문서 선택 보존 규칙을 유지한다.
- `panelId`를 전달하면 탭의 `aria-controls`와 본문의 `aria-labelledby`를 연결할 수 있다. Slides·Site의 속성 패널은 이 연결을 사용한다.
- 탭 이름은 자르지 않고 가로 스크롤한다. 선택한 탭이 가려지면 탭 목록 안에서 보이게 이동한다. 문서 화면 전체를 스크롤하지 않는다.
- `NavigationItem`은 페이지로 이동하는 버튼이다. 선택·hover·키보드 포커스를 구분하며, 선택 테두리는 사방이 같은 두께다. 아이콘과 보조 표시는 고정 폭을 유지하고 긴 이름은 줄바꿈한다. 호스트가 `aria-current`와 실제 이동 동작을 제공한다.
- `EmptyState`는 제목·설명·선택적 동작을 제공한다. 빈 보관함과 빈 검색 결과의 설명을 구분한다. 검색 결과가 없어도 검색 입력칸을 유지하며 검색 지우기를 제공한다.
- 트리의 펼치기, 다중 선택, 레이어 이동은 이 일반 탐색 버튼의 역할에 포함하지 않는다. 별도 제품 모델과 명령을 유지한다.

검증: 새 브라우저 4개와 기존 네 제품 비교 1개. Note 검색 전후 선택 페이지 보존, Slides 속성 탭 이동, Site 블록 검색 초기화, 작은 화면과 두 테마를 확인했다. office-ui·갤러리 타입 검사와 Office 빌드 통과. 전체 트리·드래그 조합 검증은 다음 단계다.

## 변경 순서와 검증

1. 실제 제품에서 발생한 문제와 대상 컴포넌트를 정한다.
2. 갤러리에 재현 상태를 추가한다. hover와 focus를 CSS로 흉내 내지 않는다.
3. 공통 컴포넌트나 토큰을 수정한다.

현재 갤러리는 기본 토큰, 버튼·입력·선택·색상, 메뉴·다이얼로그, 저장·복구, 탐색·레이어 상태와 작업 예시를 다룬다. 툴팁·문맥 도구와 데이터 그리드 상태는 후속 검토 대상이다. 기존 전체 컴포넌트 목록은 참고 목록으로 유지하며, 모든 항목을 새 기준으로 승인한 것으로 취급하지 않는다.


## 입력·선택 기준 — 2026-09-14

상세 화면: `/design-system/index.html#fields`.

- TextField: 검색은 입력마다 갱신한다. 문서 속성은 Enter 또는 blur에서 적용하고 Escape로 취소한다. 조합 중 Enter는 확정 처리를 하지 않는다. 확정형 입력은 앞뒤 공백을 제거해 표시 값과 적용 값을 맞춘다.
- NumberField: 표시 자릿수와 저장 정밀도를 구분한다. 입력하지 않고 포커스만 옮기거나 Escape를 눌러도 저장 값은 변하지 않는다. 직접 입력도 min/max 범위를 따른다. onClear가 없으면 빈 입력을 이전 값으로 복원한다. 숫자 일부만 읽어 잘못 적용하지 않는다. 드래그 취소는 적용하지 않는다.
- ChoiceSelect: 입력칸의 긴 값은 말줄임한다. 포털 목록은 전체 이름을 줄바꿈하고 스크롤한다. 키보드 End로 마지막 항목에 접근할 수 있으며 Escape는 목록을 닫고 포커스를 복원한다. invalid와 describedBy로 오류와 설명을 연결한다.
- 읽기 전용, 비활성, 혼합 값은 서로 다른 상태다. 오류 테두리는 hover와 focus에서도 유지한다.

브라우저 13개(입력·선택 4, 버튼 3, 기존 갤러리 5, 실제 네 제품 비교 1), 숫자 입력 단위 12개, 갤러리·office-ui 타입 검사와 Office 앱 빌드를 검증했다. 조합 검사는 브라우저 composition 이벤트 경계를 다룬다. 운영체제의 실제 한글 입력기 후보 창을 자동 검증한 것은 아니다.

## 색상·메뉴 기준 — 2026-09-14

- ColorPicker는 248px 폭에 색상판, HEX, 불투명도, 테마·변수·최근 색상을 배치한다. 색상표는 24px 선택 영역과 사방의 선택·포커스 표시를 사용한다.

- 불투명도는 NumberField를 사용한다. Enter·blur에서 0–100 범위로 적용한다. 빈 입력은 이전 값을 복원한다. 색상판 드래그와 완성된 HEX 입력의 기존 실시간 적용은 유지한다.
- ColorField는 제목과 닫기 버튼을 제공한다. 팝업 전체를 화면 안으로 제한하고 내부 스크롤을 허용한다. 닫기와 Escape는 입력 포커스를 색상 버튼으로 돌려준다. 속성 행 label이 닫기 클릭을 다시 전달해 팝업을 여는 동작을 막는다.
- Menu는 방향키·Home·End로 실제 포커스를 이동하고 비활성 항목을 건너뛴다. 긴 항목은 줄바꿈하며, 긴 목록은 내부에서 스크롤한다. Enter/Space는 한 번 실행한다. Escape·Tab으로 닫고 기존 포커스를 복원한다.

## 트리·레이어 기준 — 2026-09-14

상세 화면: `/design-system/index.html#layers`.

- `office-layer-row`는 34px 행과 사방 선택 테두리를 제공한다. `data-row-selected`, `data-row-hidden`, `data-row-drop=before|after|into`로 상태를 전달한다.
- `office-layer-pick`은 객체 선택 버튼이다. 펼치기 버튼과 `LayerActions`는 형제 요소로 둔다. 버튼 안에 다른 버튼을 넣지 않는다.

- Slides 드래그는 명령을 한 번 실행하며 한 번의 undo로 되돌린다. React 상태 갱신 함수 안에서 문서 명령을 실행하지 않는다. Site는 Escape·pointercancel 또는 목록 밖에서 놓으면 드롭을 취소한다.

## 툴팁·문맥 도구 기준 — 2026-09-14

상세 화면: `/design-system/index.html#context`.

- Tip은 포털로 표시한다. 최대 너비는 280px이며 화면 여백은 8px이다. 긴 설명은 줄바꿈하고 단축키는 한 묶음으로 유지한다.
- 툴팁은 포커스를 가져오지 않는다. FloatingSurface 내부에서는 Escape가 툴팁을 먼저 닫고, 다음 Escape가 문맥 도구를 닫는다.
- ContextToolbar는 위치와 선택 정체성을 구분한다. Escape로 닫은 뒤 같은 선택의 위치만 달라지면 다시 열지 않는다. 새 선택에서는 다시 표시한다.

- 텍스트를 드래그하는 동안과 조합 입력 중에는 문맥 도구를 숨긴다. 창이 포커스를 잃으면 임시 입력 상태를 해제한다.

## 복합 속성 패널 — 2026-09-14

상세 화면: `/design-system/index.html#properties`.

- PropertyGroup 제목은 긴 경우 줄바꿈한다. 접기 버튼과 초기화 버튼은 각각 동작한다. 같은 제목의 그룹도 고유한 본문 ID를 사용한다.
- PropertyRow는 입력의 배치 그룹이다. 내부 입력과 버튼은 각자의 이름을 제공한다. 행 전체를 label로 감싸지 않는다.
- PropertyToggle의 `value: null`은 혼합 상태다. 체크박스에 가로선과 `aria-checked="mixed"`를 표시한다. Space나 클릭은 선택한 대상 모두에 켜짐을 적용한다.
- 숫자 혼합 값은 `null`로 전달해 —를 표시한다. 포커스만 옮겨서는 값을 적용하지 않는다. 제품에서 속성 기본값을 먼저 해석한 뒤 혼합 여부를 계산한다.
- PropertyGroup의 `onReset`, `resetLabel`, `resetDisabled`로 초기화를 연결한다. 제품이 변경 범위와 실행 취소를 처리한다. 버튼 이름은 변경할 속성을 명시한다.
- Slides 선택 그룹은 회전 0°와 불투명도 100%만 초기화한다. 위치·크기·표시·잠금은 유지한다. 잠긴 대상이 있으면 초기화할 수 없다. 변경은 하나의 명령으로 실행한다.

검증: 새 브라우저 2개, 네 제품 비교 1개, 입력·모달 회귀 9개. 혼합 체크의 키보드 입력, 접은 그룹 초기화, 좁은 화면과 두 테마, Slides 다중 선택·잠금·초기화·실행 취소를 확인했다. office-ui·갤러리 타입 검사와 Office 빌드 통과. Slides는 기존 미사용 항목 검사를 제외한 타입 검사 통과. 다른 제품의 속성별 초기화 범위는 후속 적용이다.


## 데이터 표 — 2026-09-14

상세 화면: `/design-system/index.html#data-table`.

- `DataTable`은 native table 구조와 공통 표면을 제공한다. thead·tbody·th는 호출자가 작성한다. 완전한 ARIA grid 또는 데이터 모델을 제공하지 않는다.
- `DataTableRow selected`는 선택 배경을 표시한다. 선택 제어는 PropertyToggle로 연결한다. 일부 행만 선택하면 전체 선택의 값은 null이다.
- `DataTableCell`의 `numeric`, `readOnly`, `invalid`는 숫자 정렬·읽기 전용·오류 표시다. 실제 입력 비활성화와 설명은 호출자가 제공한다.
- 행 선택은 배경, 셀 포커스는 안쪽 네 면 테두리로 구분한다. 내부 입력을 `data-cell-editor`로 표시하면 셀 테두리를 유지하고 입력의 중복 테두리는 제거한다.
- 숫자는 오른쪽 정렬과 고정 숫자 폭을 사용한다. 계산 오류에는 설명과 오류 테두리를 함께 표시한다. 계산 셀도 키보드로 접근할 수 있어야 한다.
- 넘치는 표는 호출자의 스크롤 컨테이너 안에서 이동한다. 문서 전체의 가로 너비를 늘리지 않는다.

Note에 공통 표와 행 체크박스를 적용했다. 데이터 명령·필터·범위 붙여넣기·저장은 Note가 유지한다. Enter는 변경이 없는 입력도 종료하고, Escape는 초안을 버리고 셀로 포커스를 돌린다. 기존 방향키 이동이 계산 셀에도 도달한다.

검증: 새 브라우저 2개, 네 제품 비교 1개, Note 일괄 변경·고급 일괄 변경·범위 붙여넣기 3개. 밝은·어두운 테마, 390px 가로 스크롤, 실제 저장 후 재열기를 확인했다. office-ui·갤러리 타입 검사와 Office 빌드 통과. Note 타입 검사는 기존 미사용 항목 검사를 제외했다. 범위 드래그 선택, 가상 스크롤과 전체 grid 키보드 모델은 후속 범위다.


## 좁은 도구 모음 — 2026-09-14

상세 화면: `/design-system/index.html#overflow`.

- 한 줄 Toolbar에 `overflow`를 사용한다. `RibbonToolbar compact`는 이를 기본 적용한다.
- 도구가 모두 들어가면 추가 버튼을 표시하지 않는다. 넘치면 오른쪽 36px 영역에 도구 찾기 버튼을 고정한다. 기존 가로 스크롤도 유지한다.
- 메뉴에서 그룹을 고르면 해당 그룹의 첫 사용 가능한 컨트롤로 이동한다. 이름 없는 그룹은 각 컨트롤의 이름을 사용한다. 숨김·비활성 컨트롤은 이동 대상에서 제외한다.
- 입력과 명령을 메뉴 안에 다시 만들지 않는다. 기존 컨트롤의 DOM과 제품 명령을 사용한다. 키보드 포커스 이동도 도구 모음 안의 가로 위치를 갱신한다.
- 메뉴는 공통 FloatingSurface와 MenuAction을 사용한다. 화면 안에서 줄바꿈·스크롤하며 방향키·Home·End·Escape로 조작한다. Escape는 실행 버튼으로 포커스를 돌린다. 바깥 클릭은 클릭한 대상의 포커스를 유지한다. 화면 크기를 바꾸면 메뉴를 닫는다.
- FloatingSurface의 처음 포커스는 배치가 끝나고 표면이 보이는 시점에 설정한다.

검증: 새 브라우저 2개, 네 제품 비교 1개, 모달·문맥 도구 8개. 갤러리의 입력값 유지·한 번 실행·두 테마·390px 경계, Word 선택 서식, Slides 740px와 Site 560px에서 기존 도구로 이동을 확인했다. office-ui·갤러리 타입 검사와 Office 빌드 통과. 전체 모바일 편집기 레이아웃이나 모든 도구의 명령 실행 인증을 뜻하지 않는다.


## 반응형 작업 공간 — 2026-09-14

상세 화면: `/design-system/index.html#workspace`.

- AdaptiveWorkspace는 자기 영역의 너비를 측정한다. 기본 기준은 960px이며 `breakpoint`로 조절한다. `enabled={false}`인 관리 화면에는 패널 전환 도구를 표시하지 않는다.
- WorkspaceSidePanel의 navigation·inspector는 넓은 화면에서 나란히 배치된다. 좁은 화면에서는 기본 접고 하나씩 캔버스 위에 연다. 이때 캔버스의 너비는 줄이지 않는다.
- 패널은 hidden으로 접는다. 다시 열 때 같은 입력과 탐색 탭을 사용한다. 패널을 열면 첫 사용 가능한 컨트롤로 포커스를 옮긴다.
- 캔버스 영역에 `data-workspace-main`을 지정한다. 이 영역의 클릭은 패널만 닫으며, 캔버스의 원래 클릭 동작을 막지 않는다. 입력칸 밖 Escape는 패널을 닫고 실행 버튼으로 포커스를 돌린다. 입력과 중첩 메뉴가 먼저 처리한 키는 가져가지 않는다.
- 넓은 화면으로 전환하면 두 패널을 복원한다. 좁은 화면으로 다시 전환하면 둘을 접어 작업 공간을 확보한다. 화면별 보기 상태는 문서 저장 데이터에 넣지 않는다.

Site에 먼저 적용했다. 560px에서 캔버스 너비 550px 이상, 1440px에서 기존 패널과 탐색 탭 복원을 확인했다. 공통 갤러리는 390px 패널 경계와 입력값 유지를 검증했다. 새 브라우저 2개와 기존 제품·도구 모음 3개, office-ui·갤러리 타입 검사 및 Office 빌드 통과. Site 앱 전체 타입 검사는 별도 undefined 인수 2건과 markdown-it 선언 누락 1건이 남아 있다. 이후 Slides에도 같은 규칙을 적용했다. Note의 좁은 화면 적용은 후속 범위다.


### Slides 적용 — 2026-09-14

슬라이드 목록과 컴포넌트 목록은 navigation 패널에 둔다. 넓은 화면에서는 가로로 배치하고, 좁은 화면에서는 세로로 배치한다. 발표 중에는 패널의 내용뿐 아니라 래퍼도 숨긴다. 캔버스의 전역 키 처리보다 열린 패널의 Escape 처리를 우선한다.

검증: 작업 공간 브라우저 3개와 기존 도구 모음·네 제품 비교 3개가 통과했다. 390px·560px·1440px 전환, 선택한 객체의 너비 변경과 유지, 레이어 탭 유지, 발표 진입·종료를 확인했다. Slides 타입 검사(기존 미사용 항목 제외)와 Office 빌드가 통과했다. 작은 화면의 헤더 높이·눈금자 숫자 간격·타임라인 밀도는 다음 개선 범위다.


### 작은 화면 헤더와 눈금 — 2026-09-14

- EditorHeader의 명령 영역은 메뉴와 문서 작업을 함께 배치한다. 700px 이하에서 문서 정보, 명령, 보기 도구를 나눈다. 컨트롤을 복제하거나 상태를 다시 만들지 않는다. 넘친 영역은 가로로 이동한다.
- scaledAxisStep은 현재 화면 배율에 따라 눈금의 major·minor 간격을 함께 늘린다. 1·2·5 계열을 쓰며 단위와 원점을 유지한다. Slides에 적용했다. 기본 숫자 간격은 42px 이상이다.
- Slides의 접힌 타임라인은 제목과 재생 도구를 유지한다. 시간축 확대·클릭 순서·성능 안내는 펼친 상태에서 표시한다. 타임라인 제목과 도구는 줄바꿈하지 않는다.

검증: 축 단위 검사 13개, 새 작은 화면 브라우저 1개, 기존 작업 공간 3개와 네 제품 비교 1개가 범위별 통과했다. 390px·560px·1440px, 25% 눈금, 발표 버튼 경계, 시간축 확대 실행을 확인했다. office-ui 타입 검사와 Office 빌드가 통과했다. Note의 작은 화면 작업 공간은 다음 단계다.


### Note 탐색 패널 — 2026-09-14

- AdaptiveWorkspace의 `panelSides`는 실제 사용하는 탐색·속성 버튼을 지정한다. Note는 탐색만 사용한다.
- `locationKey`가 바뀌면 열린 패널을 접는다. 포커스가 접힐 패널 안에 있으면 `data-workspace-main`으로 옮긴다. 이 동작을 사용하는 본문 호스트에는 `tabIndex={-1}`을 지정한다.
- Note 보관함은 닫아도 제거하지 않는다. 검색어와 선택 페이지를 유지한다. 검색 목록에서 페이지를 선택해도 검색 조건을 유지한다. 참조 링크와 기록 이동은 기존 초기화 규칙을 따른다.
- 툴팁은 닫힐 때 종료 애니메이션을 사용하지 않는다. 닫히는 Radix 레이어가 Escape를 계속 가져가는 것을 막는다. 열기 애니메이션은 유지한다.

검증: 공통·Site·Slides·Note 패널 4개, 모달 5개, 문맥 도구 3개 브라우저 검사가 범위별 통과했다. 390px Note의 작성 내용·검색·페이지 이동·포커스 복귀와 1440px 패널 복원을 확인했다. office-ui 타입 검사와 Office 빌드는 통과했다. Note 전체 타입 검사에는 기존 markdown-it 타입 선언 누락 1건이 남아 있다.


### Word 보기 도구와 문서 배율 — 2026-09-14

- Word의 ZoomControl은 EditorHeader의 `view` 영역에 둔다. 상세 리본을 접어도 배율 입력과 너비 맞춤을 사용할 수 있다. Ribbon의 `externalZoom`은 호스트가 배율 도구를 제공할 때 중복 표시를 막는다. 기본값은 기존 패키지 사용 방식을 유지한다.
- 문서 배율은 office-word가 관리한다. ZoomFrame은 용지의 고유 크기를 유지하고 화면에 그린 크기만 스크롤 영역에 반영한다. 문단 크기와 페이지 나눔은 배율 때문에 바뀌지 않는다.
- 눈금자는 문서 패널의 크기와 가로 스크롤을 따른다. 호스트가 넘긴 패널 안에서 용지를 찾는다.
- 작은 화면의 문서 작업 버튼은 줄바꿈하지 않는다. 넘치는 작업은 공통 헤더의 가로 스크롤로 접근한다.

검증: 작은 화면·네 제품 비교 2개, Word 배율 6개, 수식·객체 5개, 인쇄 6개가 범위별 통과했다. Word 타입 검사(기존 미사용 항목 제외)와 Office 빌드 통과. 다음은 Word 개요·댓글 패널에 공통 적응형 작업 공간을 적용하고 작성 중인 댓글을 보존하는 작업이다.


### Word 제품 메뉴·검토 패널 — 2026-09-14

- EditorHeader의 `fallbackNavigation`으로 단독 호스트의 제품 메뉴를 제공한다. 통합 호스트가 등록한 탐색 메뉴가 있으면 그것을 먼저 사용한다. Word 단독 화면은 문서 보관함·문서 작업을 제공하고, 통합 화면은 자료함·연결한 자료를 제공한다.
- AdaptiveWorkspace의 `activePanel`·`onActivePanelChange`로 외부 메뉴와 패널의 열림 상태를 연결한다. `onCompactChange`는 호스트에 작은 화면 여부를 알린다. `panelLabels`로 Word의 개요·댓글 이름을 표시한다. 기존 비제어 사용 방식은 유지한다.
- Word는 넓은 화면의 패널 설정과 작은 화면의 임시 패널을 별도로 관리한다. 댓글 입력 컴포넌트의 상태를 유지해 초안을 보존한다. Escape는 패널을 닫고 해당 패널 버튼으로 포커스를 돌린다.
- 즉시 반영되는 TextField는 취소할 임시 값이 없으므로 Escape를 상위 UI에 전달한다. 확정형 필드와 IME 조합 중 Escape는 기존 입력 소유권을 유지한다.

검증: 공통 패널·필드·모달·Word 초안·제품 비교 15개, 단독 Word 메뉴 1개, Word 배율 1개 브라우저 검사가 범위별 통과했다. 390px·560px·1440px 패널 전환, 초안 보존과 실제 댓글 등록을 확인했다. 새로고침 후 초안 복구는 별도 기능이다.

### 네 제품 메뉴와 보기 도구 — 2026-09-14

- ProductMenu는 단독 앱과 통합 호스트에서 같은 제품 이름·화살표·메뉴 상태를 표시한다. 메뉴 항목과 저장 처리는 호스트가 제공한다. 제품별 메뉴 CSS를 복제하지 않는다.
- Note·Word·Slides·Site 단독 앱은 EditorHeader의 `fallbackNavigation`에 ProductMenu를 넣는다. 통합 호스트는 등록된 탐색 메뉴를 먼저 사용해 메뉴가 중복되지 않는다.
- 배율과 미리보기 등 보기 도구는 EditorHeader의 `view`에 둔다. Site도 이 위치를 사용하며 관리 화면에서는 숨긴다. 편집 명령은 아래의 기본 도구 모음에 둔다.
- 미리보기처럼 켜짐 상태가 있는 텍스트 버튼에는 공통 Button의 `pressed`를 사용한다.

## 팝업 작업 영역 — 2026-09-14

- `FloatingPanelHeader`는 제목과 닫기 버튼을 같은 행에 표시한다.
- `FloatingPanelFooter`는 `leading`에 초기화 등 보조 작업을, `children`에 취소·적용을 받는다. 좁은 화면에서는 줄을 바꾼다. 저장 로직과 포커스는 호스트가 담당한다.
- 적용은 `Button tone="accent"`, 취소는 기본 버튼을 사용한다. 처리 중 중복 실행을 막고 상태를 표시한다.
- `Button`은 네이티브 버튼의 `ref`를 받는다. 팝업 기준 위치와 닫기 후 포커스 복원에 사용한다.
- Note 필터·정렬·새 보기에 적용했다. 필터 모델과 저장 명령은 office-note에 남긴다. 속성 표시는 공통 `PropertyToggle`을 사용한다.
- 갤러리 `#panel-actions`는 임시 값 유지, 취소, 오류 후 재적용을 보여준다. 예시의 실패 스위치는 실제 저장 오류가 아니다.

```tsx
<FloatingPanelFooter leading={<Button tone="quiet" onClick={reset}>초기화</Button>}>
  <Button disabled={saving} onClick={cancel}>취소</Button>
  <Button tone="accent" disabled={saving || !valid} onClick={apply}>적용</Button>
</FloatingPanelFooter>
```

## 다중행 입력 — 2026-09-14

- `TextAreaField`에 `onChange`를 주면 기존 실시간 입력으로 동작한다. `onChange` 없이 `onCommit`을 주면 초안을 편집한다. 두 방식을 함께 전달하지 않는다.
- 확정형 입력은 Enter로 줄을 바꾸고 Ctrl/⌘+Enter 또는 blur로 적용한다. Escape는 마지막 적용 값으로 되돌리고 포커스를 해제한다. 공통 Dialog·Drawer·FloatingSurface 안에서도 먼저 입력을 취소한다.
- 한글 조합 중 Enter·Escape는 확정·취소로 처리하지 않는다. 앞뒤 공백과 줄바꿈을 자르지 않는다.
- `onCommit`은 void, boolean, 또는 그 Promise를 반환한다. false 또는 예외면 초안을 유지하고 오류·다시 시도를 표시한다. 성공 여부를 알 수 있는 호스트는 boolean을 반환한다.
- 처리 중 입력은 읽기 전용이며 중복 호출을 막는다. 부모 value가 변경되면 새 값을 반영한다. 항목이 바뀌면 호스트는 해당 항목 ID를 key로 사용한다.
- `readOnly`, `disabled`, `invalid`, `describedBy`, `inputRef`, `data`를 지원한다. 검증과 저장 대상은 호스트가 관리한다.
- Site longText 셀과 행 Drawer에 적용했다. 숫자 변환과 서식 있는 본문 편집은 기존 경로를 사용한다.
- 갤러리 `#multiline`에서 실시간·확정·오류·대기 상태를 확인한다. 대기·실패 스위치는 로컬 예시다.

```tsx
<TextAreaField ariaLabel="설명" value={description}
  onCommit={value => saveDescription(value)} rows={3} />
```


## 검색 결과 이동 — 2026-09-14

- `SearchResultNavigation`은 검색어, 현재 인덱스(0부터), 결과 개수, 이동 콜백을 받는다.
- 빈 검색어는 입력 안내, 결과 0개는 검색 결과 없음을 표시한다. 결과가 없거나 disabled면 이전·다음 버튼을 비활성화한다.
- `children`에는 대소문자 구분 같은 검색 옵션을 추가할 수 있다.
- Note의 `DocumentNavigation`과 Word의 `FindPanel`이 같은 결과 행을 사용한다.
- 검색·바꾸기·결과 위치 이동·실행 취소는 제품이 관리한다. 결과 행은 문서와 에디터를 참조하지 않는다.

```tsx
<SearchResultNavigation query={query} current={activeIndex} count={matches.length}
  onStep={direction => moveMatch(direction)} />
```

- 재시도는 원래 대상과 변환된 값을 사용한다. 선택 대상·슬라이드·문서·단위가 바뀌면 이전 오류와 입력 초안을 지운다.

## 색상·숫자 입력의 키보드 규칙 — 2026-09-14

- ColorField를 Enter·Space로 열면 색상 코드에 포커스를 주고 값을 선택한다. 포인터로 열 때는 포커스를 강제로 옮기지 않는다.
- Escape로 닫으면 원래 색상 버튼으로 돌아간다. Tab으로 컨트롤 밖에 이동하면 팝업을 닫고 이동한 곳의 포커스를 유지한다.
- 긴 색상 이름은 행 안에서 줄여 표시한다. 전체 이름은 title로 제공하며, 색상 버튼과 지우기 버튼의 크기를 유지한다.
- NumberField의 ↑·↓는 step 단위로 초안을 조정한다. Shift는 10배, Alt는 1/10 단위다. 둘 다 누르면 Shift가 우선한다. min·max·decimals 규칙을 따른다.
- 방향키 조정은 즉시 문서에 기록하지 않는다. Enter·Tab·blur로 확정하며 Escape는 취소한다. 편집하지 않은 표시 값은 원래 저장 정밀도를 유지한다.
- 데스크톱 브라우저 검사에서 실제 Slides 도형의 확정 전 상태 유지와 한 번의 실행 취소를 확인했다. 모바일 검사는 포함하지 않았다.

## 채우기·효과 편집 행 — 2026-09-14

- StackRow는 editorLabel·onEditorClose·editorTriggerRef로 편집 제목, 닫기 버튼, 키보드 포커스를 제공한다. 기존 편집 영역이 없는 행은 그대로 사용할 수 있다.
- 키보드로 열면 첫 입력으로 이동한다. 닫기 버튼 또는 편집 영역 안에서 Escape로 닫으면 원래 버튼으로 돌아간다. 다른 곳으로 이동한 포커스는 빼앗지 않는다.
- Slides 채우기와 효과 색은 같은 편집 행을 사용한다. 그라디언트의 색 지점·정렬·단위 변환과 캔버스 축은 Slides가 관리한다.
- 패널 색 지점은 Enter·Space로 선택한다. 위치 숫자로 조정할 수 있으며, 순서가 바뀌어도 같은 색을 선택한다.
- 패널의 지점 드래그는 막대와 위치 입력에서 미리보기한다. 놓을 때 문서에 한 번 적용하고, Escape는 미리보기만 취소한다. 캔버스 축 드래그와 구분한다.
- Site는 시작·끝 색 모델을 유지한다. ColorField·PropertyNumber로 색과 값을 편집하고 모양은 선형·원형으로 표시한다.

## 이동 가능한 속성 편집 창 — 2026-09-14

- ColorField와 StackRow의 floatingEditor는 공통 useMovablePanel로 배치·이동한다. StackRow에는 editorTriggerRef와 제목·닫기 동작을 함께 제공한다.
- 속성 패널 왼쪽에 먼저 배치한다. 공간이 없으면 반대쪽을 시도하고 화면 가장자리에서 8px 안쪽으로 제한한다.
- 제목 영역을 드래그하면 위치가 바뀐다. 이동한 창은 속성 패널 스크롤이나 값 변경으로 원래 자리로 돌아가지 않는다. 닫고 다시 열면 기준 위치에서 시작한다.
- 이동 중 Escape는 이동만 취소한다. 평소 Escape와 닫기 버튼은 창을 닫고 원래 버튼으로 돌아간다. 제목의 닫기 버튼에서 드래그를 시작하지 않는다.
- manual popover의 최상위 표시 영역을 사용한다. DOM·테마·비활성 fieldset 소속과 기존 바깥 클릭 감지는 유지한다. 모달 배경을 추가하지 않는다.
- 최대 높이는 화면 안으로 제한한다. 제목과 닫기 버튼은 고정하며 본문만 스크롤한다. 화면 안에서 창을 옮기는 동작은 문서 변경 이력을 만들지 않는다.


## 데스크톱 기본 UI 마감 — 2026-09-14

- 이동 가능한 색상 창은 안쪽 컨트롤의 너비를 통일한다. ColorPicker는 패널의 가용 너비를 채운다. 스크롤 본문은 색상 막대 손잡이가 잘리지 않도록 좌우 8px 공간을 둔다.
- StackRow의 `order: { up?, down? }`는 편집 창 제목에 순서 변경 버튼을 표시한다. 경계 방향은 비활성이다. 순서 변경은 편집 창을 닫고 실행한다. `useStackOrder.move(from, to)`와 행 드래그는 같은 이동 연산을 사용한다.
- 드래그는 행의 실제 경계를 측정한다. 효과 종류에 따라 행 높이가 달라져도 대상 행을 올바르게 찾는다. 문서 변경은 드래그 종료 시 한 번만 요청한다.
- 여러 수치를 함께 표시할 때 항목 이름과 단위를 생략하지 않는다. Slides 효과는 가로·세로·흐림·확산과 pt를 표시하며, 문서 단위 변환은 제품이 처리한다.
- 현재 기본 UI 정비를 1차 마감한다. 제품별 선택·명령 연결은 office-editor-ui에서 계속 진행한다. 모바일과 서버 기반 공유·권한 UI는 별도 범위다.


### 색상과 채우기 합성의 경계

ColorPicker는 색상·색상 알파·테마 색·스포이드를 제공한다. 혼합 모드는 해당 채우기가 아래 내용과 합성되는 방식이므로 제품의 채우기 설정에 둔다. StackRow의 `details`는 팝업을 열지 않아도 보여야 하는 행 설정을 받는다. Slides는 이 영역에 채우기별 혼합 모드를 표시한다. 혼합 모드 변경과 문서 저장은 제품이 처리한다.


### 색상 입력 형식 — 2026-09-14

- ColorPicker는 HEX·RGB(A)·HSL·HSB·OKHSL 형식 선택을 제공한다. 선택은 열린 피커의 UI 상태이며 문서 값을 변경하지 않는다.
- RGB는 0–255, 색조는 0–360°, 채도·명도·밝기는 0–100%로 입력한다. HSB는 HSV의 B(밝기) 표기다. A는 색상 알파이며 채우기 전체 불투명도와 다르다.
- OKHSL 변환은 Color.js 0.7.1의 변환 API를 사용한다. 숫자를 확정할 때 기존 제품이 읽는 sRGB HEX/RGBA로 내보낸다. 넓은 색역의 원본 보존이나 CSS OKHSL 저장을 제공한다는 뜻은 아니다.
- 표시 형식만 바꾸어도 양자화하거나 실행 취소 기록을 만들지 않는다. 다른 채널과 알파를 유지하며 변경한 채널만 반영한다. 회색·검정에서 색조·채도를 먼저 지정한 값은 현재 입력 세션에서 보존한다.
- 채널 입력은 공통 NumberField의 확정·취소 동작을 사용한다. HEX 입력과 팝업 포커스 규칙은 유지한다.
- 변환 근거: [Color.js procedural API](https://colorjs.io/api/modules/index_fn.html).
