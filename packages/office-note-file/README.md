# @barocss/office-note-file

Private Node.js bundle of the Note snapshot codec. Its build uses the same source implementation as `@barocss/office-note/file` and produces a self-contained ES module. The API service must build this package before loading it from a workspace checkout.

`serializeNoteFile` writes deterministic bytes when given the same document and `savedAt`. `readNoteSnapshotFile` validates a Note file and preserves its optional `savedAt`. `copyNoteSnapshotFile` accepts a server-issued new page ID and rewrites the root and its own page references. The service owns authentication, ID issuance, idempotency, hashing, and database transactions.

For migration input, `savedAt` is optional. Any nonempty JSON string is preserved verbatim, even if it is not an ISO date. An empty or non-string value returns `{ error }` from the reader; the serializer throws for an invalid explicit value.

Malformed source files return `{ error }` from the copy function. The new page ID is a server-owned invariant: it must pass `isNotePageId` and differ from the source page ID. An invalid or unchanged new ID throws. The service must not pass a client-supplied ID to this function.

## Full Note collaboration seed contract

`NOTE_FULL_SEED_V2` is separate from the narrow `note-text-seed-v1` diagnostic. `parseFullNoteSeedSource` rejects duplicate JSON keys, unknown envelope/node/attribute/mark fields, invalid Note structure, and non-JSON data before any ID callback runs. It keeps the exact PostgreSQL snapshot string and its SHA-256. It does not take the normalized product reader output as the migration source. Nested resources, database records and item-body rich text remain in the recursive tree; resource IDs, row IDs, dataset names and page references are data, not newly minted node identities.

The service supplies a trusted page ID and `mintNodeId` callback to `createFullNoteSeed`. The callback must return unique `node:`-namespaced IDs. The service must persist the complete seed, source revision, source hash, stable IDs and attempt identity atomically **before** Yorkie I/O. On retries or after restart, it must reuse that persisted seed rather than call the minter again. A legacy file without `pageId` receives the server page binding in the canonical tree without rewriting the frozen source string. `typedFullNoteSeedTree` commits to every canonical field, ordered marks, and an explicit `yorkie.Text` tag for each text field. The resulting canonical tree hash is distinct from the source-byte hash.

`createInitialFullNoteSeedRoot` reserves exactly `{ wonfficeSeed, note, editProofs }`. The immutable marker binds seed attempt, document key, provider project/build, stable page ID, snapshot revision, source hash and canonical tree hash. `editProofs` is a separate, append-only **provider-operation** namespace. Each proof needs actor, session, edit ID and operation hash. It is empty at seed time and excluded from the historical seed-tree hash. `decodeInitialFullNoteSeedRoot` enforces an unchanged initial tree and empty ledger. `decodeFullNoteSeedRoot` checks a live root's shape but does not reapply the historical seed hash to edited content. These pure shape checks do not prove Yorkie origin, actor authorization, append-only history, actual `yorkie.Text` runtime types or durable acceptance. The server must validate those facts through a fresh authorized provider client and its own persisted attempt/provenance records; a caller-created `editProofs` object is never sufficient proof.

The current codec preserves legacy callout titles and other source fields without silently rewriting them. A product mount adapter must preserve canonical node IDs when applying any legacy display normalization; `openNoteTree` alone may add a title child or math boundary runs and cannot be treated as a lossless canonical round trip. External media bytes and access rights are outside this codec and require live authorization at UI access. This package does not promote a document, write a provider root, or establish full Note alpha readiness.
