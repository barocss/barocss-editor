# Word document and selection chrome

The Word app keeps permitted writing continuous. Its idle header retains the document title, menus, command search, document actions, status and zoom. An explicit full-tool button expands the existing ribbon and ruler. There is no manual reading/writing preference.

Ribbon document presentation is opt-in. Default consumers keep their existing compact and expanded ribbon. The Word app keeps the Ribbon and math editing hooks mounted while collapsed. Owned non-collapsed text selections show Word style, font, character, color, paragraph, list and link tools. Selected tables and pictures show their existing Word object controls in a wrapping band with natural height. Their multi-row size and placement controls do not use the fixed-height compact text strip. The full ribbon and menus retain the complete command set.

Selection command ownership binds the exact editor, native root object, range, datastore version and monotonic selection/content/authority lifetime. Deferred font delivery checks that captured intent again. Changing a selection away and back does not revive a prior command. Keyed selection tool children retire portalled fields and palettes when their target lifetime changes. Selected style, font and size menus receive the exact contextual chrome ref as their optional portal container. Text and object surfaces portal into the untransformed document pane while their selection ownership still uses the original editor scope. This keeps viewport coordinates separate from Word zoom transforms. Default and expanded menus keep their original portal behavior. Shared contextual surfaces retain their existing Escape, explicit reselection, viewport and focus behavior.

Current host and editor authority remain the mutation boundary. Viewer comments can open, select threads and close; comment add/edit/reply/resolve/delete controls are disabled and guarded. View navigation, search, outline, zoom and print remain available through existing host controls. Viewer selection does not activate formatting or object mutation tools.

Native and focused mounted checks cover tool-only native equality, meaningful paragraph-style undo/redo, changed/revoked/replaced targets, A to B to A and A to cleared to A refusal, viewer thread navigation and live comment authority revocation. Final desktop/authenticated/API/PostgreSQL evidence must identify the exact integrated candidate. Physical Korean IME remains separate from synthetic event tests. This UI change does not prove omitted-marks exact restoration for the #420 preview-only proposal, four-product completion or alpha readiness.

Same-account Word permission refresh keeps the mounted runtime and protected pending bytes. Live authority is checked before and after delayed import/recovery/save preparation. A viewer demotion cannot replace the document or send a later frozen write; promotion can retry its original key and bytes. Actual account/document/mode boundaries remain required.

Browser-origin DOM selections update the model without replaying the same range into the DOM. The replay previously suppressed a following real selection event, leaving the model at a partial range after rapid keyboard selection. Explicit programmatic model-to-DOM commands retain their existing behavior. Forward/backward rapid-selection regression compares the latest endpoints and unchanged native document. A user selection reported during programmatic caret restoration is deferred through the owning view’s timer until restoration ends, rather than dropped. The existing focused-view, scope, node-selection hold and debounce rules still apply. Leaving the editor or destroying that view cancels this ownership; programmatic commands still control model-to-DOM restoration.

Owned selection menus close before their parent tool surface on Escape and return focus to their trigger. Dismissing the remaining tool surface with Escape returns owned tool-field focus to the current editable document without changing its model or history. Outside dismissal does not move focus. This lets the next real cell click establish its own selection instead of restoring a stale text range during editor focus.
