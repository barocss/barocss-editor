# Wonffice 서비스·Agent 아키텍처

## 결정과 범위

클라우드 SaaS와 고객사 내부 설치 제품을 **동시에 출시한다**. 이는 사용자가 선택한 출시 조건이다. 한 코드베이스와 같은 배포 이미지로 두 환경을 지원한다. 제품 서버는 개발자 컴퓨터와 분리한다. 개발은 Codex가 활성 작업을 시작·재개할 때 GitHub 이슈·PR을 먼저 확인하는 방식이다. 독립 상주 실행기는 후속 선택이다.

이번 산출물은 설계 기준과 구현 순서다. `ready_for_build`는 첫 작업 WP-01을 구현할 수 있다는 뜻이다. 백엔드, 무인 Agent, 배포 환경이 구현되었다는 뜻이 아니다. 후속 기준점 저장 작업에서 GitHub 이슈·PR을 연결한다. 자동 실행 등록과 외부 서비스 배포는 수행하지 않는다.

| 사용자 요구 | 설계 기준 | 구현 완료 증거 |
| --- | --- | --- |
| R1 클라우드·내부 설치 | 같은 버전·이미지, 환경별 설정, 내부 설치도 첫 출시 필수 | 두 환경에서 설치·수정·공유·업데이트·복원 검사 통과 |
| R2 고객사별 기능 | tenant별 기능 설치·설정·권한. 고객사별 코드 포크 금지 | A사 전용 기능을 B사가 API로도 실행할 수 없음 |
| R3 GitHub 자동 개발 | 이슈→계획→격리 작업→검사→PR→정책에 따른 병합 | 실제 이슈 1건의 전체 실행 기록, 실패 시 병합 차단 |
| R4 Codex 활성 작업 중 자동 진행 | 시작·재개 시 GitHub 우선 확인, 진행 기록·예산·중간 지시 | Codex 재개 후 최신 이슈·PR을 확인하고 중복 작업 없이 진행 |
| R5 작업 중 의견 반영 | 요청 버전, 우선순위, 일시 정지·취소, 오래된 결과 차단 | 중간 지시 후 이전 요구 기준의 PR이 자동 병합되지 않음 |
| R6 서비스 백엔드 | 계정·회사·권한·문서·자산·공유·작업·감사 | 서로 다른 두 회사의 자료 격리와 저장·복구 검증 |

## 문서의 역할

- [플랫폼 설계](../../../docs/specs/wonffice-platform.md): 서비스 경계, 데이터와 실행 계약, 두 배포 환경.
- [Agent 실행 설계](../../../docs/specs/wonffice-agent-runtime.md): GitHub, 로컬 작업자, 자율 실행 정책, 중간 지시.
- [구현 순서](../../../docs/specs/wonffice-platform-delivery.md): WP-01부터 WP-12까지 의존 관계와 완료 검사.
- [기존 제품 범위](../../../docs/specs/wonffice-delivery-scope.md): 제품 기능과 첫 출시 범위. 이번 설계는 이 문서의 4–5단계를 구체화한다.

## 이번 점검 결과

Codex 흐름 연결: 기준점 이슈 [#248](https://github.com/barocss/barocss-editor/issues/248)와 WP-01 이슈 [#249](https://github.com/barocss/barocss-editor/issues/249)를 생성했다. 통합 Office 빌드는 통과했다. 전체 타입 검사는 office-note·office-slides·apps/site에서 실패했다. 기준점 PR은 draft로 검토하며 main 병합은 별도 검증 단계다.

편집기의 operation·transaction·제품별 codec은 재사용한다. 직접 Agent 도구로 공개하지 않는다. 실패 정리, 결과 상태, 버전·권한·중복 요청 처리부터 보강한다. 로컬 workspace는 서버 계정·저장·권한을 제공하지 않는다.

기존 개발 가이드의 무한 이슈 생성 규칙을 승인된 작업 목록과 예산에 따르는 대기 규칙으로 수정한다. 현재 공유 작업 디렉터리의 변경은 보존한다. 향후 무인 실행기는 별도 관리 clone에서 명시한 기준 commit으로 작업한다.

## 보류하지 않고 구현 시 결정할 항목

호스팅 업체, OIDC 공급자, 객체 저장소 제품, 내부 설치 기준 Linux 배포판과 최소 자원은 WP-05에서 비교·실험 후 고정한다. 외부 계정·요금·DNS 정보는 해당 배포 단계에 필요하다. 이 선택 때문에 WP-01의 실패 처리 보강을 미루지 않는다.

첫 내부 설치는 단일 Linux 서버의 컨테이너 배포를 기준안으로 잡는다. 폐쇄망 설치용 이미지·설정·업데이트 묶음을 제공한다. 고가용성 클러스터와 고객사마다 다른 운영체제 지원은 첫 출시 범위에 넣지 않는다. 모바일 편집 설계·화면 검사는 이번 범위에서 제외한다.
