# Site product foundation

기준일: 2026-09-13. 실행 범위는 `docs/specs/wonffice-delivery-scope.md`의 T1–T3다. 실제 호스팅·도메인·폼 수신은 서버를 연결하는 4–5단계에 남긴다.

## 현재 상태

- T1 페이지·반응형 작성: 기존 구현을 인수 검사 중이다. 다중 폭, 페이지 이동, 속성, Note 본문 입력을 범위별로 확인했다.
- T2 컴포넌트·CMS·미디어: 기존 구현을 전체 브라우저 회차에서 검사 중이다.
- T3 저장·출력: 자동 저장·문서 ID·최근 자료·충돌 초안·실패 재시도를 새로 연결했다. 기존 JSON/HTML/ZIP 출력은 중첩 본문을 먼저 반영한다.
- 남은 순서: 전체 회차의 실패 판정·수정 → 실제 다중 페이지 결과물 출력 확인 → 통합 작업 공간.

## 이번 구현

- `shared/DocumentSession`: 제품별 코덱·메타데이터·저장소를 받는 공통 저장 수명 관리. 조건부 쓰기는 기존 `DocumentSaveQueue`가 수행한다.
- Slides `DeckAutosave`는 공통 세션의 어댑터로 변경했다. 저장소 이름과 기존 문서 ID는 유지한다.
- `office-editor-ui/LocalDocuments`: 저장 상태·최근 자료·초안 복구·오류 재시도 UI를 공유한다. Slides와 Site에 적용했다.
- Site는 `barocss-site-workspace/documents`, `barocss-site-recovery/drafts`를 사용한다. URL의 `#site=<UUID>`가 문서 ID다. 기존 이름 기반 파일 라이브러리는 유지한다.
- 새 사이트·파일 열기 전에 현재 자료를 저장한다. 실패하면 현재 자료를 유지한다. 최근 자료를 열면 관리 화면으로 복귀한다.
- 중첩 Note는 `beforeinput` 단계에서 저장 대기를 표시하고, 본문 flush 후 스냅샷을 저장한다. `input`만 관찰하면 코어가 기본 입력을 취소하는 경로에서 마지막 글자를 놓쳤다.
- 메뉴/저장과 편집 도구를 두 줄로 나누었다. 실제 브라우저에서 보인 버튼 글자 꺾임을 수정했다. 제목은 Wonffice Site로 맞췄다.
- 출력용 PAGE_CSS에 본문의 제목 간격·토글·체크리스트·자료 참조 스타일을 보완했다.
- Node의 JSON 모듈 로드 오류 때문에 브라우저 검사 수집이 중단됐다. `math-editor/src/i18n.ts`의 JSON import에 형식 속성을 명시해 수집을 복구했다.

## 검증 기록

- 공통 저장 큐/세션 단위 9개 통과: 안정적 ID, 중첩 입력 반영, 읽는 동안의 수정 보존, 쓰기 실패 재시도, 입력 무변경 시 상태 복원.
- Site 자동 저장·충돌·파일 저장·중첩 본문 닫기/출력 11개 통과. Slides 저장·충돌·복구 회귀 4개 통과.
- Site 첫 단위 회차: 646개 중 641개 통과, 출력 스타일 검사 1개와 오래된 명세 수치 4개 실패. 출력 스타일 보완 후 관련 12개 통과. 명세의 21개 추가 노드(기존 Site 14개 + 임베디드 prose 7개)와 현재 숫자를 수정한 명세 검사 6개 통과.
- 첫 브라우저 회차: 47개 중 39개 통과, 8개 실패. 고정 Note toolbar를 기대하는 오래된 검사를 문맥 도구로 바꾸었다. 실행 중 모듈 연결 변경으로 로드가 중단된 항목도 있었다. 변경 후 해당 작성·반응형 회차 11개 전부 통과.
- 메뉴·키보드 표시·테마 팔레트 10개 통과. Site 생산 빌드 성공. 공통 패키지의 기존 TypeScript 진단은 아직 남아 있다.
- 실제 사용자 브라우저: 새 Site 자료에서 홈 이름을 “Wonffice 소개”로 변경하고 최근 자료에서 재열었다. ID와 변경이 유지된다. 문서 URL은 `http://localhost:5182/#site=b16f3f9a-1dd1-4922-9969-d343053e0576`이다. 본문 샘플은 배포용 서비스 소개가 아닌 편집 표본이다.

전체 인수 회차 로그: `/tmp/site-product-acceptance.log`. 아직 결과 확인 전이며 완료로 표시하지 않는다.
